# 出口本地预测、动作条件路径传播与 TT 整表安全重编排

**英文题目：** Egress-Local Prediction and Action-Conditioned Path Propagation for Safe Whole-Table TT Reconfiguration in TSN

各出口从本口全部可见 AVB/BE 事件预测 ST 到达本口队列的分布。上游出口先提出 $\delta$ 参数化的 TT 整表动作，确定性 Service Mapper 将其本地 ST 预测、候选 TT/Flex 和冻结时可得的本地服务状态映射为下游到达消息；消息仅沿预先固定的 ST 路径单向发送。下游 Actor 同时读取自己的本地预测与这些动作条件消息，提出本口 TT 整表动作。全部候选最终进入不读取 ST 预测的合同型联合安全链，经 Compiler/Validator 和一致提交后，在下一超周期边界统一激活。

$$
\boxed{\text{本地感知与预测}\;\to\;\text{DAG 分层提案与单向传播}\;\to\;\text{合同型整表安全执行}}
$$

以 Topology-v1 的上游 $u$、下游 $d$ 为例，主链冻结为

$$
\begin{aligned}
\mathcal H_{e,k}^{local}&\xrightarrow{f_\psi}p^{loc}_{g,e,k}=(q^{loc}_{g,e,k},\boldsymbol\pi^{loc}_{g,e,k}),\quad\forall e\text{ 并行},\\
o^{base}_{u,k}&\xrightarrow{\pi_\theta}\boldsymbol\delta_{u,k}
\xrightarrow{D(\cdot;\mathbf x^{cur}_{u,k})}\hat{\mathbf x}_{u,k}
\xrightarrow{\text{已有安全工具的局部预检查}}(\mathbf x^{pre}_{u,k},G^{pre}_{u,k}),\\
(\{p^{loc}_{g,u,k}\}_g,G^{pre}_{u,k},\eta^{local}_{u,k})
&\xrightarrow{\mathcal S_u}\{\mu^{TX}_{g,u,k}\}_g
\xrightarrow{\mathcal P_{u\to d}}m_{g,u\to d,k},\\
[o^{base}_{d,k},\mathbf m_{\mathrm{pa}(d)\to d,k}]
&\xrightarrow{\pi_\theta}\boldsymbol\delta_{d,k}
\xrightarrow{D+\mathrm{precheck}}\mathbf x^{pre}_{d,k},\\
\{\mathbf x^{pre}_{e,k}\}_e&\xrightarrow{\Gamma_{time}}\tilde{\mathbf x}_k
\xrightarrow{\mathrm{Compiler+Validator+C2/C3}}G_{k+1}.
\end{aligned}
$$

$\eta^{local}$ 是冻结时可得的队列、残帧与服务状态及其因果外推信息，具体近似见第三部分。$G^{pre}$ 是性能传播所依据的预检查候选，尚无安装权限；$G^{exec}$ 是最终实际运行表，两者分别记录。

```text
各口 32 ms AVB/BE 历史 → 四口 Local Predictor 并行
                         ↓
                  A3u ∥ A4u：整表 δ
                         ↓
            Decoder + 局部预检查 → 候选 TT/Flex
                         ↓
                 Service Mapper（确定性）
                         ↓
      m_A: e3u→e01   m_B: e4u→e01   m_C: e4u→e02
                         ↓
      A01 ∥ A02：自己的 local prediction + 接收的 message
                         ↓
      四口候选 → Γ_time → Compiler/Validator → C2/C3
                         ↓
                 t_k+8 ms 统一激活

仅离线：实际网络与源帧账本 → E2E 团队回报 → Critic/GAE → 更新 Actor
```

**Local sensing + structured predictive communication + local whole-table proposals + E2E training + contract-only safety.** 在线预测协作用显式的动作条件消息表达上游动作影响，集中 Critic 仅用于训练。预测消息不进入安全层，安全层只按固定合同修正与准入。

# 第一部分 研究对象、问题、工况与贡献

## 1.0 全文统一叙述口径（最高约束）

1. **本地 Predictor 保留。** 每个出口仅从转发至本口的全部 AVB/BE `RX_COMPLETE` 事件建立 $\mathcal H_e^{local}$，对每个 $g\in\mathcal G_e$ 输出自己的 $p^{loc}_{g,e}$。下游本地预测始终存在；原始历史、Set Transformer 嵌入、ModernTCN 隐状态不跨口传输。真实相关流名单不进入在线输入。
2. **固定路径上的动作条件传播。** 上游先提出本口整表动作，再根据本地预检查候选与本口服务状态形成下游到达分布。仅允许发送 route-constrained propagated arrival message；下游 Actor 将该消息和自己的本地预测并列使用。首版不将两者按独立证据相乘，也不新增融合预测网络。
3. **整表动作权限。** $a_{e,k}=\boldsymbol\delta_{e,k}\in[-1,1]^{N_e}$，确定性 Decoder 以本轮 $\mathbf x^{cur}_{e,k}$ 为参考生成 $\hat{\mathbf x}_{e,k}$。$\boldsymbol\delta_e=\mathbf0$ 表示保持当前表的提案；最终执行仍可能被联合安全修正。**坐标属于 TT flow，动作属于整张 TT 表。** 固定周期实例顺序，逐帧验证、整表原子安装。
4. **路径是固定部署与消息路由元数据。** 路径不学习、不在线优化或改变；用于本口任务归属、TT 安全、E2E accounting 及预测消息路由。由固定路径导出的出口消息图须经无环检查并冻结拓扑层次；Actor 不输入完整路径、hop index 或拓扑编码。
5. **分层执行仅一次前向。** 全部 Predictor 并行；$(A_{3u}\parallel A_{4u})\to\mathcal P\to(A_{01}\parallel A_{02})$。性能消息无反向边、无循环等待、无迭代重规划。Safety 的 PREPARE/COMMIT 应答是既有事务协议，不能夹带性能反馈或触发 Actor 重算。
6. **两个通信白名单分开。** 性能通道只传候选版本绑定的下游到达分布及有效性元数据；安全通道只传 TT 提案、硬合同、安全摘要与提交元数据。安全层不接收 $q,\pi,p^{loc},p^{prop},z^{pred}$，不按 ST 收益选表、重试或优化。
7. **CTDE 与实际执行。** Predictor/Actor/Critic 参数分别为 $\psi,\theta,\phi$，只允许同类参数跨口共享。在线本地历史和隐藏状态隔离；Actor 的跨口信息入口仅为白名单消息。离线 Critic、E2E 回报与集中缓存在部署时移除；训练与测试均运行相同 DAG、Service Mapper、消息失效规则和安全链。

| 角色 | 输入与输出 | 权限边界 |
|---|---|---|
| Local Predictor | 本口 AVB/BE 历史 → $p^{loc}_{g,e}$、仅本口使用的 $z^{pred}_e$ | 不读取其他出口历史、消息或 TT/ST 事件来扩展预测域 |
| Actor | 本地预测/资源 + 固定父边的有效消息 → 本口整表 $\boldsymbol\delta_e$ | 不控制其他出口，不在线读取集中 Critic |
| Service Mapper / Propagator | 本口 ST 预测、候选 TT/Flex、本口冻结服务状态 → 下游到达消息 | 确定性服务回放；不新增预测网络，不搜索下游动作 |
| Contract-only Safety | TT 候选 + 硬合同/过渡摘要 → $\tilde{\mathbf x}$、硬核验与提交 | 不读取 ST 预测或按性能收益调整 |
| 集中 Critic | 当前集中训练摘要 → 价值估计 | 仅离线训练，无在线调度权限 |

路径的统一英文口径为：**Routes are fixed deployment and predictive-communication metadata, not learned features or decision variables.** 方法定位为 **decentralized actors with route-constrained one-way communication**。局部预测、前向性能协调和合同安全分别有明确接口。

## 1.1 研究对象：可预测的自触发流（ST）

Self-triggered Traffic（ST）是由终端内部任务状态触发的控制指令，例如 AMR 避障制动、多机械臂协作修正、电机异常保护。它具有以下特征：

- **自触发、非周期。** 是否发出以及何时发出由任务状态机决定，不设置固定触发周期或固定相位。
- **可预测性是待验证的本地假设。** 隐藏任务状态可能同时改变若干普通流的包事件。本文检验：在当前交换机转发至同一出口的 AVB/BE 事件中，多流联合关系能否提供超出先验与最佳单流的预测信息。事件是样本单位，FlowID、帧长、优先级和时刻是事件属性。
- **在线不知道相关流名单。** 模型接收本出口所有可见 AVB/BE 事件，包括无关背景流，不按“已知与哪组 ST 相关”筛选。生成器中的真实受调制集合 $\Pi_g^{\mathrm{true}}$ 只用于解释和特权消融，不提供给在线预测器、Actor 或在线安全协调层。
- **单次触发产生单帧指令。** MAC 长度为 64–128 B，各组按任务配置后固定。主工况要求每个 $(g,e)$ 的每个 8 ms 本地服务周期最多一帧新入队；同组多事件移至第二阶段扩展，不靠只取首帧掩盖。

“可预测”分为下一周期是否到达当前出口队列，以及首帧落在哪个 0.5 ms 格。任务检测到发出的延迟记为 $T_g^{\mathrm{dec}}$，帧长记为 $L_g$。保留 ST-A 的 12 ms、ST-B 的 9 ms 决策延迟与 0.1 ms 抖动作为生成器参数；它们不能直接证明每个出口在冻结前已有可见前兆。源端检测、普通包到达本出口、ST 到达本出口之间均有物理传输过程，必须逐 $(g,e)$ 测量提前量。

冻结在 $t_f=t_k+4$ ms，目标是 $C_{k+1}=[t_k+8,t_k+16)$ 内的**本出口队列到达**。冻结后才出现前兆、但 ST 仍在目标周期到达的样本保留为正样本，并单独报告性能；弱前兆、无前兆及只能判断发生的组也不从评价分母删除。低信息时允许输出接近先验的分布，低信息时仍执行同一整表提案接口。

| 属性 | 定义 | 说明 |
|---|---|---|
| 帧 | 单次触发一帧；MAC 64–128 B，按组配置后固定 | 原稿以 3GPP TS 22.104 运动控制报文作应用参照，应用载荷与 MAC 帧长口径分开 |
| 端到端截止期 | 全部 ST 组 $D_g=1$ ms，从源端释放到目的端接收完成计时 | 本轮正式冻结主值；0.5 ms 预测分格不是服务槽或截止期 |
| 到达方式 | 任务状态机触发，非周期，相位不固定 | ST-A、ST-B、ST-C 分别对应避障、协作修正、电机保护 |
| 到达合同 | 主工况 $N_{g,e,k}\in\{0,1\}$，覆盖全部六个本地任务 | 源恢复、决策抖动与全允许服务域共同支持；源端限次不自动推出下游限次 |
| 预测对象 | 每个 $(g,e)$ 的未来本地队列到达 | 同一 ST 帧在不同出口的到达可以属于不同周期 |

## 1.2 本地预测、动作条件传播与联合安全

研究问题是：在固定路由、TT 实例顺序及 TT/AVB 硬合同下，能否保留各出口普通流中的本地证据，又显式提供上游本轮 TT 动作造成的下游到达变化，从而改善 ST 真实 E2E delay/miss？TT 重编排改变 Flex 的位置、连续性与 GB 开销，链路容量保持为固定的 1 Gb/s。

令 $e=(v,p)\in\mathcal E_c$，$P_g$ 为 ST 的固定物理路径，

$$
\mathcal G_e=\{g:e\in P_g\},\quad
\mathcal O_e=\{f\in AVB\cup BE:f\text{ 转发至出口 }e\},\quad
\mathcal T_e=\{i:e\in P_i^{TT}\}.
$$

| 出口 / Agent | 物理链路 | 保留的本地预测任务 | 前向消息 |
|---|---|---|---|
| $e_{3u}/A_{3u}$ | S3→S0 | $(A,e_{3u})$ | 发 $m_A$ 至 $e_{01}$ |
| $e_{4u}/A_{4u}$ | S4→S0 | $(B,e_{4u}),(C,e_{4u})$ | 发 $m_B$ 至 $e_{01}$，$m_C$ 至 $e_{02}$ |
| $e_{01}/A_{01}$ | S0→S1（P1） | $(A,e_{01}),(B,e_{01})$ | 接收 $m_A,m_B$ |
| $e_{02}/A_{02}$ | S0→S2（P2） | $(C,e_{02})$ | 接收 $m_C$ |

控制层次为 $\mathcal L_1=\{e_{3u},e_{4u}\}$、$\mathcal L_2=\{e_{01},e_{02}\}$。终端接入及末端链路仍使用静态基线，计入真实 E2E 时延。$e_{01}$ 不读取转发至 $e_{02}$ 的普通事件；同机共享进程不扩大观测域。

**TT 整表提案。** 每口一次采样/输出 $a_{e,k}=\boldsymbol\delta_{e,k}$，再由当前表参考的 Decoder 产生 $\hat{\mathbf x}_{e,k}$，同流全部周期实例通过固定锚 $\zeta_{J,e}$ 展开。TT 每流固定 $L_i\in\{500,1000\}$ B MAC，每源周期一帧、$D_i=T_i$、固定源相位与 $J_i^{src}=0$。精确映射见第五部分；$\delta=0$ 是 KEEP 提案，原始动作、预检查候选、最终执行分别记录。

**已有工具的局部预检查。** Decoder 后复用 $\Gamma_{time}$ 的本口约束模式与现有 Compiler 的预览模式，检查本口可核的 release、固定实例顺序、non-overlap、tick、FIFO 必要条件与 GCL 条目，形成 $(\mathbf x^{pre}_e,G^{pre}_e)$。它只做预先固定的合同修正，不含 ST 性能目标，不新增一个调度优化器。预检查不代替最终多跳 FIFO、AVB 与过渡认证。局部失败时本口预候选固定为当前认证表并记录原因；不重跑 Actor 或重试性能候选。

**最终安全链保留两层。**

$$
(\tilde{\mathbf x}_k,\mathrm{status}^{time}_k)
=\Gamma_{time}(\mathbf x_k^{pre};\mathbf x_k^{cur},\mathcal C_{time},B_{time}).
$$

第一层只核必要 envelope、源释放、固定计划顺序、跨跳因果、TT 期限与时间栅格，在预算内返回经复核的可行点或失败状态，不承诺精确最近点。第二层 Compiler/Validator 检查真实 Q6 FIFO trace、实际 TT 因果与期限、GB/GCL、固定 AVB 净预约以及旧→新过渡。只有第二层及 C2/C3 全部及时通过才有安装权限：

$$
\mathbf x_k^{exec}=\begin{cases}
\tilde{\mathbf x}_k,&\text{完整硬核验及一致及时提交通过},\\
\mathbf x_k^{cur},&\text{否则}.
\end{cases}
$$

$\mathcal F_{install}\subseteq\mathcal F_{time}$，投影通过或本地编译成功均不等于可部署。各阶段按状态顺序调用，失败后不使用未定义输出、不继续 ST 性能搜索。安全层可为跨跳合同修正相关口的提案，因而 $G_u^{exec}$ 可能不同于传播采用的 $G_u^{pre}$；该差异按第四部分审计，本轮不回传重规划。

硬安全仍以 TT 确定性、硬件、固定 AVB 预约服务与可验证过渡为准。ST 的 1 ms 和 AVB 的 2 ms 软时延目标不作为安全安装门槛。AVB 净服务认证须覆盖固定 ST 干扰包络、信用与过渡状态，预测置信度不能替代硬边界；认证完成范围与仿真观察分开报告。

第 4 ms 冻结全部本地历史和资源输入；所有模型、两层 Actor、Mapper、前向消息、联合安全及提交共同使用余下 4 ms，第 8 ms 统一激活。当前表整个周期持续执行。消息使用认证的管理服务机会，其占用、残帧阻塞、通信延迟和并发争用计入完整预算。

## 1.3 三个核心模块与一次 DAG 前向控制

1. **Egress-local correlation prediction。** 保留 4×8 ms 本地 AVB/BE 事件历史；Set Transformer 提取窗内多流关联，ModernTCN 提取跨窗演化，双头逐 $(g,e)$ 输出 $p^{loc}_{g,e}$。
2. **Action-conditioned path propagation。** Service Mapper 根据本口候选 TT/Flex 和可用本地服务状态，对本口 ST 竞争联合回放，得到发送完成分布，再沿固定路径映射为下游入队消息。具体假设、跨周期覆盖和失效处理见第三部分。
3. **Prediction-guided whole-table TT reconfiguration。** 上游 Actor 用本地预测，下游 Actor 用自己的本地预测和传播消息，均输出完整 $\boldsymbol\delta_e$。固定路径 DAG 规定先后关系，MAPPO 用真实 E2E 团队回报离线训练这些条件策略。

合同型安全链是执行保障，继续使用既有 $\Gamma_{time}$、Compiler/Validator 和 C2/C3，不另列新的学习方法模块。

$$
\boxed{\underbrace{\text{四口 Local Predictor 并行}}_{\text{本地证据}}
\to\underbrace{(A_{3u}\parallel A_{4u})\to\mathcal S+\mathcal P\to(A_{01}\parallel A_{02})}_{\text{固定 DAG 的一次前向}}
\to\underbrace{\Gamma_{time}\to C1/C2/C3}_{\text{合同准入}}}
$$

| 接口 | 内容 |
|---|---|
| 采集→Predictor | 本口全部已到达 AVB/BE，$t^{RX}<f_k$；无真相关名单 |
| 本地 Predictor→本口 Actor | $p^{loc}_{g,e}$ 与仅本口使用的 $z^{pred}_e$ |
| Actor→Decoder→局部预检查 | 整表 $\boldsymbol\delta_e$ → 原始 $\hat{\mathbf x}_e$ → $\mathbf x^{pre}_e,G^{pre}_e$ |
| Service Mapper→固定子边 | 候选版本绑定的 $p^{prop}$、有效性/覆盖元数据；不发送 GCL 或隐藏表示 |
| 下游 Actor | 将本地预测和父边消息并列输入；无乘积概率融合、无新预测网络 |
| 候选→Safety | $\mathbf x^{pre}$、当前表与硬合同；不含预测消息 |
| 联合时间修正→最终编译/验证 | $\tilde{\mathbf x}$ → 完整硬检查 → 版本、哈希、共同激活点 |

算法一对应既有本地事件预测，算法二对应单次 DAG 前向与既有安全事务。新增内容仅是 Service Mapper 和其输出消息协议；预检查是已有安全/编译工具的局部复用，实验审计是证据要求。

相关工作与外部基准分两层处理：外部复现基准锁定同属“标准同步 IEEE 802.1Qbv 门控下混合 TT + ST/ECT 调度”的 **ARTSN** (*IEEE ICDCS 2023*)、**E-TSN** (*IEEE ICDCS 2021*) 与 **Period**（标准周期静态 TAS 基线 $G^0/\mathbf x^0$，区别于内部校准集调优的 `StrongStatic`），在 **star（主设 Topology-v1）** 与 **line（4 受控口串联拓扑 `Topology-Line-4`）** 两套形态上同底线评测；而改变底层同步 802.1Qbv 硬件执行模型的 **eTAS** (*IEEE IoT-J 2021*)、**ATAS** (*JNSM 2022*)、**InNetScheduler** (*IEEE ICNP/TON*) 以及依赖全网跨节点时空图注意力历史共享的 **GP-TSN** (*IEEE/ACM IWQoS 2025*) 作为相关工作深入讨论其硬件与可观测性假设边界，不作实验复现对照。主指标包括全部 ST 源帧 E2E miss/尾部时延、逐任务本地预测、传播精度（$D_{map}$）及版本一致性（$D_{prop}$）、TT/AVB 合同、GB/GCL 和整链耗时。

## 1.4 工况与应用依据

| 项目 | 主设 | 说明 / 敏感性 |
|---|---|---|
| 链路与门控 | 1 Gb/s，$H=8$ ms，$\Delta_g=80$ ns | 不支持帧抢占；保护带向上对齐为 12.4 μs |
| ST | MAC 64–128 B，每事件一帧，$D_g=1$ ms | 各组长度在该范围内按任务固定；事件/恢复参数另行冻结，单事件准入仍须验证 |
| 队列 | Q7 ST、Q6 TT、Q4 AVB、Q0 BE | 整张 TT 时间表联合重编排；Flex 内非抢占 $ST>AVB_{CBS-eligible}>BE$ |
| TT 长度/工作量 | 每流固定 500/1000 B；五类周期各每次一帧 | 流数与负载由唯一全局流表重算，不预设每口流数或固定 TT 百分比 |
| AVB / BE 负载 | AVB 各口已知固定 $R_e^{AVB}$；BE 64–1518 B | 各口预约数值、BE offered rate/arrival model 待登记；不由帧长范围推断总负载 |
| 拓扑 | Topology-v1；主控制集合 $\{e_{3u},e_{4u},e_{01},e_{02}\}$ | 固定路由；接入与末端链路计入端到端时延 |
| AVB 软时延目标 | $D_{target}^{AVB}=2$ ms | 报 P50/P95/P99 与超过目标比例；固定预约与 CBS 仍是硬约束 |

原稿应用参照：[3GPP TS 22.104 表 5.2-1](https://whatthespec.net/friendlyspec/spec/22.104/19.2.0)。具体业务期限、载荷与 MAC 帧长对应关系须在实验配置冻结时核验；本轮不新增应用实测结论。

**ST 主截止期正式冻结为 1 ms。** 全部组采用 $D_g=1$ ms，在本轮定义后、正式训练/最终测试前登记配置版本。校准轨迹只用于合法工作点与模型/控制参数，不再挑选主截止期；测试无收益或超时仍如实报告。其他期限只能作为预先声明的敏感性，不能替代主值或用测试结果追选。

ST 端到端计时仍为 $t_g^{\mathrm{dest}}-r_g^{\mathrm{src}}$，不在中间出口重新开始。局部动作与集中训练不保证全局最优，需报告相对强静态、局部规则及相同权限 Oracle 的差距。

# 第二部分 系统模型、本地观测与控制时序

## 系统模型

将 TSN 网络建模为有向图

$$
\mathcal G = (\mathcal V, \mathcal E)
$$

其中，$\mathcal V$ 表示网络中的终端设备与 TSN 交换机集合，$\mathcal E$ 表示交换机之间以及终端与交换机之间的有向链路集合。本文假设网络拓扑固定，所有链路速率统一为

$$
\boxed{C_e = 1\text{ Gb/s}, \qquad \forall e \in \mathcal E}
$$

对于任意业务流 $f_i$，其转发路径均由网络配置阶段预先确定，不考虑在线路径规划与路由调整；固定路径用于部署归属、逐跳合同验证、预测消息路由与离线评价，不作为 Predictor/Actor 的学习路径特征。记流 $f_i$ 的固定路径为

$$
P_i = \left( e_{i,1}, e_{i,2}, \ldots, e_{i,H_i} \right)
$$

其中 $H_i$ 表示该流路径包含的链路跳数。

网络采用统一时间同步机制，各交换机按照共同的调度周期执行 Gate Control List（GCL）。由于 TT 流周期取值集合为

$$
T_i \in \{0.5, 1, 2, 4, 8\}\text{ ms}
$$

因此采用其最小公倍数作为统一超周期：

$$
\boxed{H = 8\text{ ms}}
$$

GCL 的基础时间栅格设为

$$
\boxed{\Delta_g = 80\text{ ns}}
$$

因此一个超周期包含

$$
N_g = \frac{H}{\Delta_g} = \frac{8\text{ ms}}{80\text{ ns}} = 100000
$$

个基础时间栅格。

主设单口 GCL 内存预算 $B_{GCL}=256$，当前属于代表性仿真硬件模型假设，不声称所有 TSN 设备统一支持 256 条。若后续绑定设备，须补型号、固件/驱动和限制依据；否则保持仿真定位，并按 $128/256/512$ 做条目预算敏感性。TT 发送实例数与 GCL 实际条目数分开计算。

网络不支持 Ethernet Frame Preemption，因此低优先级帧一旦开始传输，在发送结束之前不能被高优先级业务中断。为避免非抢占帧跨越 TT 门控边界并阻塞 TT 发送，在 TT 保护区（TT protected region）前设置保护带。保护带按照最大非抢占帧长度

$$
L^{GB} = 1542\text{ B}
$$

计算，在 $1\text{ Gb/s}$ 链路上的理论持续时间为

$$
\frac{1542 \times 8}{10^9} = 12.336\ \mu\text{s}
$$

结合 $80\text{ ns}$ 时间栅格向上对齐后，实际采用

$$
\boxed{155 \times 80\text{ ns} = 12.4\ \mu\text{s}}
$$

作为 GCL 编译阶段的保护带长度。BE 生成器最大 MAC 1518 B，按既定 20 B 线上开销为 1538 B；1542 B 是统一保守 blocking bound，多出的 4 B 是认证裕量，不额外计入业务负载。AVB/管理帧等所有可能残留的非抢占帧也必须满足该线上上界，未知长度不能默认满足；超过该界须重新认证 GB。保护带按 TT protected region 前置，不是每个 TT 帧各加一个。

网络业务划分为 TT、ST、AVB 和 BE 四类，其中仅 TT 业务进行确定性的时隙编排；ST、AVB 与 BE 在 TT 与保护带之外形成的 Flex 区域中进行在线发送，并按照

$$
\boxed{\text{non-preemptive }ST > AVB_{CBS\text{-eligible}} > BE}
$$

执行严格优先级服务。若 AVB 使用 CBS，则 AVB 仅在满足 CBS credit eligibility 的条件下参与发送。

队列映射统一为：

| 队列 | 业务 | 门控与执行 |
|---|---|---|
| Q7 | ST | Flex 内开门，异步业务中最高优先级，队内 FIFO |
| Q6 | 全部 TT | 按已认证 TT 发送计划开门，队内 FIFO |
| Q4 | AVB | Flex 内开门，满足该出口单一 CBS 的信用条件后参与发送 |
| Q0 | BE | Flex 内开门，最低优先级 |

全部 TT 都以流坐标纳入本口整张表的联合时间表示，不按权限另行分类；合法重构自由度由联合合同决定，不能由单坐标区间宽度代替。Q6 门控按队列开关，不能按 FlowID 从 FIFO 中挑帧。保留基线的 TT 帧实例发送顺序，并核对真实入队/就绪顺序与计划一致；固定计划顺序本身不等于已经满足 FIFO。

保护带主模型在每个 TT 保护区前令异步门关闭，取 12.4 μs；在所需静默部分不启动任何新帧，已有非抢占帧须在 TT 开始前完成。相邻 TT 实例可由编译器合并为同一保护区。保护区合并指异步门关闭范围的合并，不自动意味着 Q6 在其中全程开门；Q6 必须保留实现计划所需的发送子窗口。Flex 是 TT 保护区与保护带的补集，TT 分组、保护带数和 Flex 结构都由最终目标时间坐标派生。

### 0. 真实流表决定负载与事件规模

不预设每口 TT 流数、TT 负载百分比或全网总负载。唯一全局流表冻结后，逐口计算 TT 周期工作量、AVB 源 offered load/固定预约、BE offered load、ST 实际负载与 GB 代价；各量分开报告，不能用全网平均代替本口值。

进入 Predictor 的只有本出口实际可见 AVB/BE RX_COMPLETE 事件，TT 不进入关联预测。普通流数量不等于事件数；在稳定统计下可用 $H(\bar\lambda_e^{AVB}+\bar\lambda_e^{BE})$ 估计每 8 ms 平均事件数，但峰值仍受突发、路径和上游服务影响。E1 分别报告四口窗口事件数的均值/P95/P99/max/空窗率，并按真实峰值评估输入容量，不沿用旧配置的定长事件估算。

### 1. TT 流模型与整表时间表示

$$
f_i^{TT}=\langle P_i,T_i,D_i,L_i,\phi_i\rangle,\qquad
T_i\in\{0.5,1,2,4,8\}\text{ ms},\quad D_i=T_i,\quad J_i^{src}=0.
$$

每条 TT flow 在全局配置生成时从 $L_i\in\{500,1000\}$ B（MAC）选择一次并记录；选择比例、配置种子（若随机）和实际长度在 E0 前冻结，运行及各跳不重采样。主设采用较大帧、较少流，每个源周期 $T_i$ 释放一帧。各受控口约 15–30 条 TT flow 仅作初始探索量级，逐口成员、五周期配比与工作点由同一全局流表和 E0 决定，不强锁为 20。

令 $\mathcal P=\{0.5,1,2,4,8\}$ ms，$n_{e,p}=\#\{i:e\in P_i,T_i=p\}$。各口成员数、每超周期配置帧数与 TT 利用率为

$$
N_e=|\mathcal T_e|=\sum_{p\in\mathcal P}n_{e,p},\qquad
N_e^{TT-inst}=\sum_{p\in\mathcal P}n_{e,p}\frac Hp,
$$

$$
L_i^{wire}=L_i+20\text{ B},\quad \tau_i=\frac{8(L_i+20)}C,\qquad
U_e^{TT}=\frac1H\sum_{i\in\mathcal T_e}\frac H{T_i}\tau_i
=\frac1C\sum_{i\in\mathcal T_e}\frac{8(L_i+20)}{T_i}.
$$

公式统一以秒/bit/s 计算；$\tau_i$ 是实际线上发送时间，不向 80 ns 取整替代物理时间。500 B/1000 B MAC 的单帧线上发送时间分别为 4.16/8.16 μs。按周期的待冻结表为：

| 源周期 $p$ | 本口流数（由全局表派生） | 每流每 $H$ 帧数 | MAC 长度 |
|---|---|---:|---|
| 0.5 ms | $n_{e,0.5}$ 待填 | 16 | 每流固定 500/1000 B |
| 1 ms | $n_{e,1}$ 待填 | 8 | 同上 |
| 2 ms | $n_{e,2}$ 待填 | 4 | 同上 |
| 4 ms | $n_{e,4}$ 待填 | 2 | 同上 |
| 8 ms | $n_{e,8}$ 待填 | 1 | 同上 |

这些是周期工作量/负载口径。换表边界实际发送可能跨周期，须按唯一帧 ID 的完整 trace 核对；不能以周期取模掩盖漏发或重复发送。GCL 条目数由编译结果计，不等于上述帧数。

**源帧与固定 pattern。** 用 $J=(i,n)$ 唯一标识源帧，

$$
r_{i,n}^{TT}=\phi_i+nT_i,\qquad d_{i,n}^{TT}=r_{i,n}^{TT}+T_i.
$$

同一 $J$ 沿路径转发，在每口形成 $(J,e)$ 发送实例，不在下游重新生成。以合法基线定义固定参考锚

$$
\zeta_{J,e}=s^0_{J,e}-x^0_{i,e},\qquad
s_{J,e}^{plan}=\zeta_{J,e}+x_{i,e}.
$$

$\mathbf x_e=[x_{i,e}]_{i\in\mathcal T_e}$ 是整张表的时间坐标表示，一个流的周期实例共用一个坐标；Actor 一次选择整个向量。$\zeta$ 固定于配置版本，不随当前表更新；它负责实例 pattern 展开。Actor 的 $\delta$ 则相对本轮当前坐标解码为新的整表目标，两种参考各司其职。源相位、实例身份和循环发送顺序均固定，不做 permutation，也不增加逐实例自由度。

所有实例在展开时间轴检查 release、Q6 FIFO、non-overlap、cross-hop causality、$D_i=T_i$ 和新旧表拼接。时间坐标/门控边界按 80 ns 栅格约束，Q6 连续机会内的实际后继起点仍按真实帧长递推。保护区数量/长度是 Compiler 输出，不是动作身份。本文采用 **按流表示、整表决策、逐帧验证、整张 GCL 执行**。

#### 全网唯一流表与逐出口派生

正式 E0 使用唯一 $\mathcal T^{global}$，每个 TT FlowID 只有一条源记录：

$$
(i,src_i,dst_i,P_i,T_i,\phi_i,L_i,D_i),\qquad
\mathcal T_e=\{i\in\mathcal T^{global}:e\in P_i\}.
$$

AVB/BE 同样全网唯一，保存类别、源宿、路径、队列/PCP、线上长度与生成/整形合同；ST 另保存组别、源帧 ID 规则和恢复合同。生成器只在真实源端释放一次，交换机转发同一帧；逐跳发送日志复用其身份。任务隐藏状态和真实相关子集存于隔离的生成器元数据，不作为配置派生时的在线预测筛选名单。

构建顺序是：固定源宿/路径与全局 FlowID→展开源释放→派生各口成员及帧实例→重算逐口负载/队列→构建并验证基线→计算包络。校验源释放次数、逐跳守恒、无环固定路径、目的完成及唯一帧去重；真实丢失/复制作为故障记录，不能靠下游再生帧补齐。五档流数、逐流长度/源相位和合法基线未冻结时，TT 负载尚未定义，不能宣布 E0 已准入。

主实验保持 Topology-v1 与四出口。全网表、配置、基线、包络和证书绑定同一版本；单出口控制只是明确动作权限的消融，不改变流身份或本地预测目标。本轮同步方案与参数说明，不创建数值配置或流表文件。

### 2. ST 流模型与预测目标

ST 组定义为

$$
f_g^{ST}=\langle P_g,L_g,D_g\rangle.
$$

$P_g$ 为固定路径，$L_g\in[64,128]$ B（MAC）按组/任务配置后固定，每事件一帧；全部组的端到端性能期限为 $D_g=1$ ms。多帧诊断快照不作为一次 ST 指令，另列扩展业务。

任务状态机仍为

$$
\boxed{\text{风险累积}\rightarrow\text{越阈检测}\rightarrow\text{生成 ST}\rightarrow\text{保护/锁存}\rightarrow\text{恢复与重新使能}}.
$$

**主工况单事件合同。** 非周期不等于可在同一服务周期无限重触发。主实验冻结

$$
N_{g,e,k}=\#\{J:t_{g,J,e}^{Q}\in C_k\}\le1,
\qquad \forall(g,e),k,\qquad H=8\text{ ms}.
$$

该条件定义在各出口队列的新入队帧上，覆盖四口的六个任务、允许 TT 整表时间布局及新旧表切换。不同组仍可同时出现，例如 $e_{01}$ 上 A/B、$e_{4u}$ 上 B/C。到达时刻不固定，不给 ST 安排周期或固定相位。

仅限制源端某个对齐周期的触发次数不够：跨周期释放可紧邻，且上游延迟变化会把相邻帧在下游重新聚集。一种充分的准入条件是，若所有允许服务状态下

$$
d_{g,J,e}^{Q}=t_{g,J,e}^{Q}-r_{g,J}^{src}\in[\underline d_{g,e}^{Q},\overline d_{g,e}^{Q}],\qquad
T_g^{min}\ge H+\max_{e\in P_g\cap\mathcal E_c}(\overline d_{g,e}^{Q}-\underline d_{g,e}^{Q}),
$$

其中实际源释放间隔满足 $r_{g,J+1}^{src}-r_{g,J}^{src}\ge T_g^{min}$，则同组相邻本地到达间隔至少 $H$，足以保证每个半开服务周期最多一帧。$T_g^{min}$ 由任务恢复/锁存与决策抖动共同推出，不用 12/9 ms 决策延迟代替。上下界须覆盖允许 GCL 和切换；不能用性能期限 $D_g$ 或有限轨迹最大值代替。

这是一项受限主工况准入条件，不是本轮已完成的证明。E0 须冻结并验证其实现依据；若无统一包络，只能记为未准入的工况假设，不能称已验证的单事件主设。观察到 $N\ge2$ 时记录合同越界并保留全部帧与轨迹，不静默取首帧、不删样本；该结果不能继续作为已符合单事件合同的主实验。多事件为第二阶段，届时增加计数/强度表征或调整需求模型，并重新验证包络，不在本阶段混用。

#### 预测目标：ST 首帧到达当前出口队列的时间

对每个 $e\in\mathcal E_c$、$g\in\mathcal G_e$，记目标周期内实际进入本出口队列的帧数为 $N_{g,e,k+1}$，

$$
E_{g,e,k+1}=\mathbf1\{N_{g,e,k+1}=1\},\qquad
T_{g,e,k+1}^{Q,\mathrm{first}}=\min\{t_{g,J,e}^Q:t_{g,J,e}^Q\in C_{k+1}\}.
$$

主工况中 $N_{g,e,k+1}\in\{0,1\}$，首帧即该周期唯一新入队帧，保留 `first` 命名便于扩展。无到达时时间未定义，条件时间头不计算监督损失。预测为

$$
q_{g,e,k}=P(E_{g,e,k+1}=1\mid\mathcal H_{e,k}^{\mathrm{local}}),
$$

$$
\pi_{g,e,k,b}=P(T_{g,e,k+1}^{Q,\mathrm{first}}\in I_{k+1,b}\mid E_{g,e,k+1}=1,\mathcal H_{e,k}^{\mathrm{local}}).
$$

每个出口回答“下一周期会不会到我的队列，若会首帧何时到”，不回答下一跳到达。上下游分别保留本地模型；另由确定性 Service Mapper 将候选服务作用后的到达消息沿固定路径发送给下游 Actor，本地 Predictor 本身不接收该消息。

##### 三种时间戳

| 时间戳 | 含义 | 用途 |
|---|---|---|
| $r_{g,J}^{src}$ | ST 在终端释放 | 端到端性能计时起点；未来值不是模型输入 |
| $t_{g,J,e}^{Q}$ | 该帧在当前出口队列就绪 | 逐 $(g,e)$ 建立本地到达标签 |
| $t_{g,J,e}^{TX}$ | 该帧从当前出口开始发送 | 本地 GCL、队列与非抢占服务的实际结果 |

$$
r_{g,J}^{src}\xrightarrow{\text{上游物理传输/排队}}t_{g,J,e}^{Q}\xrightarrow{\text{本出口等待}}t_{g,J,e}^{TX},\qquad
t_{g,J,e}^{Q}=t_{g,J,v}^{RX}+d_{\mathrm{proc}}.
$$

$t^{RX}$ 为当前交换机入端口接收完成，主设 $d_{\mathrm{proc}}=2$ μs，不重复计入出口等待。标签按本出口队列就绪周期归属；同一帧在不同出口可落入不同周期。E2E 统计按源端唯一帧 ID 计一次。

##### 本地性与闭环标签分布

只启用 S0 Agent、上游固定时，S0 调整本地门控不会改变同一帧已发生的入队时刻。多出口同时调整时，上游 TT 变化会改变 ST 在下游的实际到达，普通包历史也可能受上游服务影响。因此 $q_{g,e},\pi_{g,e}$ 是当前运行策略和流量环境下、仅条件于本地历史的条件分布，不能声称对任意未见上游动作都精确不变。

E1 先在固定合法 GCL 下验证逐出口信息；E2 再以合法探索/训练策略产生的改表轨迹重采样和校准预测器，随后冻结预测器，完成 Actor 训练并用独立轨迹测试；各预测型对照使用同一冻结预测器，不按各自测试结果再校准。Local Predictor 仍不输入其他出口动作、GCL、历史或消息；动作影响通过独立的性能消息进入下游 Actor。按 $(g,e)$ 报告本地预测漂移，并在 E1.5 检验传播消息是否提供增量，不用它回填监督输入。

##### 汇聚出口任务

S0/P1 的 Predictor 独立从本口 AVB/BE 事件预测 A、B 到达 P1 队列，S0/P2 的 Predictor 从 P2 事件独立预测 C 到达 P2 队列；S3 上行预测 A，S4 上行预测 B、C。同一出口各组共用本地历史编码与同一张 GCL，不共享其他出口的历史。无完整相关流、弱前兆或空窗口时仍运行相同接口，并报告该任务的可预测性边界。

#### 工业任务状态机驱动的多流联合生成

隐藏状态只存在于生成器，不进入在线模型；生成器中的信号均承载在 AVB/BE 普通流上，并依固定路由物理转发。

1. **ST-A：AMR 避障制动。** 距离、接近速度、安全余量、环境复杂度和规划负载共同演化。复杂度调制 LiDAR AVB 的短时突发，负载调制另一条状态 BE 的间隔/帧长，二者形成待学习的联合事件关系。安全余量越阈且局部规划无法恢复后，经 $T_A^{dec}=12$ ms 决策延迟发出指令，进入避障恢复状态。
2. **ST-B：机械臂协作修正。** 协作误差与同步偏差演化。不同普通状态/同步流保持各自稳定的源端边际分布，通过 $\rho_B$ 改变跨流配对；由协作安全状态触发，主设 $T_B^{dec}=9$ ms。配对是否经过网络后仍能在每个本地出口识别，必须实测。触发后安全退让并重新使能。
3. **ST-C：电机保护。** 电流、温升与振动状态持续演化，调制至少两条普通 AVB/BE 遥测或周期上报流的跨窗口联合变化。周期上报属于普通业务，不因此变成 TT。风险持续达到 $T_{hold}$ 后触发并锁存，复位冷却后重新使能。

A/B 的决策抖动主设 0.1 ms；C 的保持、锁存与恢复参数在 E0 按任务依据冻结。源状态与真实受调制流名单只用于生成、解释和特权上界。在线模型接收同出口全部 AVB/BE，包括背景流。不能预先声称三组单流均无信息；E1 比较多流与最佳单流，并用保边际打乱实验区分联合关系和单流强度。

### 3. AVB 流模型：固定预约与软时延目标

AVB 具有固定源到达/带宽预约、路由和队列合同，具体包时刻和短时突发可以随任务状态变化。定义

$$
f_j^{AVB}=\langle P_j,C_j,R_j,B_j,L_j^{max},Q_j\rangle,\qquad Q_j=Q4.
$$

$P_j$ 是固定路径，$C_j$ 是业务类别，$R_j,B_j$ 是源端长期率与突发合同，$L_j^{max}$ 是最大帧长。多条 AVB 流在每口 Q4 共用一套 CBS 参数与信用状态

$$
\Theta_e^{CBS}=\{idleSlope_e,sendSlope_e,hiCredit_e,loCredit_e\}.
$$

硬保留的是这些合同、队列映射、信用演化规则及预约服务准入边界，不允许动态方法调整 reserved rate、增大 CBS 额度或重置信用。主模型明确 Q4 关门/保护带期间信用冻结，开门期间按统一 CBS 规则演化；所有对照一致，不能在不同方法间切换规则。

#### AVB 源到达、CBS 与净预约服务分开冻结

主配置的源合同作用于真实入口整形后的线上 bit 流：

$$
A_j^{src}(t,t+u)\le\alpha_j^{src}(u)=B_j+R_j u,\qquad
B_j\ge8(L_j^{max}+20),\quad u\ge0.
$$

隐藏任务可调制原始 AVB 包事件，但发送端按固定 $(R_j,B_j)$ 令牌/整形规则产生实际网络释放；所有方法共用相同规则，Actor 不调整它。源合同、整形器状态机、队列/溢出规则及应用生成时刻均入配置；下游突发仍须按真实路径和上游服务传播。预测器只读实际整形后经网络到达该口的 RX events，E1 必须重新检验这些事件的相关性，不沿用整形前的预测收益假设。

各口 AVB 带宽要求 $R_e^{AVB}$ 是部署前已知、固定的净预约合同，Actor 不控制 AVB 源率、预约或 CBS。具体四口数值须写入统一配置，不从帧长、旧 nominal load 或 $idleSlope$ 反推。本轮保留 CBS，选择规则精确写为非抢占 $ST>AVB_{CBS-eligible}>BE$；Q4 有积压但信用不足时，BE 仍可获得服务。

固定源到达 $(R_j,B_j,L_j^{max})$、各口 $R_e^{AVB}$ 和 CBS 参数是不同层次。令 $B_e^{res}=R_e^{AVB}W_e^{res}$，在下文证书适用条件下检查实际净服务；源率聚合加预留余量不能超过合同。所有允许阻塞 TT 的 AVB/管理帧都须满足线上长度不超过 1542 B 的认证界。

令 $\eta_e^{Flex}=|\mathcal F_e|/H$ 为候选表的 Flex 开放比例。在关门信用冻结、信用有界且不注入额外信用的模型下，持续执行该表时，$\eta_e^{Flex}\,idleSlope_e$ 可作长期服务能力的必要筛查；该比例来自新流表与实际 TT/GB 编译。它不等于滑动服务证书，也不能仅设置 $idleSlope_e=R_e^{AVB}$ 就宣布准入。E0 按新 TT 布局与固定业务合同选择并冻结 CBS，所有方法同值；不沿用依赖旧 TT 负载的算式结论。

CBS 参数命名可对照 [Linux CBS 原始实现](https://github.com/torvalds/linux/blob/master/net/sched/sch_cbs.c)；本方案的门控/信用组合状态机需单独实现和验证，不能用无 TAS 的信用公式替代动态 GCL 服务证明。E0 必须完整登记：

| 层次 | 冻结字段与检查 |
|---|---|
| 源/线上负载 | 每流 $(R_j,B_j,L_j^{max})$、线上开销、整形/溢出规则、nominal 与最坏包络 |
| Q4 CBS | $idleSlope_e$、$sendSlope_e=idleSlope_e-C$、$hiCredit_e,loCredit_e$ 的值/单位/来源及信用界检查 |
| 信用状态机 | 门闭冻结；门开时发送/受阻的斜率；空队列与负信用恢复规则；正信用 cap；跨周期/换表保持信用，不清零或提前夹断负信用来增加服务 |
| 预约净服务 | 源率聚合、$W_e^{res},B_e^{res},\epsilon_e$、允许初态/在途/上游突发、ST 干扰合同及持续保持/切换证书 |
| 完成状态 | 数值、配置哈希、推导/验证代码和 PASS/未准入原因；本轮未填写的字段仍是待冻结，不以默认值运行正式主实验 |

源 $R_j$、承诺净服务率 $R_e^{AVB}=B_e^{res}/W_e^{res}$ 和 $idleSlope_e$ 是三种量。各候选须核编译后的 GB/Flex、CBS 信用与 ST 干扰下净服务，不以最低开放比例或一帧信用估算替代。缺证书只能报告探索原型，不能声称硬预约已保护。

**2 ms 只作软性能目标。**

$$
D_{target}^{AVB}=2\text{ ms},\qquad
M_{AVB}=P(d_j^{AVB,E2E}>D_{target}^{AVB}).
$$

AVB 软时延从应用包生成到目的接收完成计时，包含入口整形等待；所有对照同口径，另报网络释放后的分量。统计 P50、P95、P99、最大时延和 $M_{AVB}$，报告分母及未完成帧；此定义不改变 ST 的源释放计时。它不是 Validator 的安装拒绝条件，也不要求本阶段完成 CBS + 动态 TAS 下的 AVB 端到端 2 ms 形式证明。软目标超时必须如实报告，不能称硬合同违约。

**固定预约必须有有效服务边界。** 仅保持 $R_j,B_j,\Theta_e^{CBS}$ 或开放比例不变，不能排除长关门与 Q7 干扰使 Q4 缺乏服务。E0 冻结各出口聚合预约的保守服务证书，例如：对任意长度 $W_e^{res}$ 的滑动区间，在 Q4 持续积压、固定 ST 到达包络、允许信用状态及新旧表切换下，净 AVB 服务满足

$$
S_e^{AVB}(t,t+W_e^{res})\ge B_e^{res},\qquad
\frac{B_e^{res}}{W_e^{res}}\ge\sum_{j:e\in P_j}R_j+\epsilon_e,
$$

$S$ 与 $B^{res}$ 按相同线上 bit 口径，$\epsilon_e>0$ 为事先固定的容量余量。也可使用等价保守服务曲线；窗口、服务量和余量对所有方法相同，不按 ST 预测或测试表现调整。这是聚合 Q4 的预约服务下界，不冒充逐流 2 ms E2E 保证。Validator 核验证书适用性或保守服务界；无适用依据的候选不能宣称已保护硬预约。

最低开放比例 $\eta_e^{Flex}\ge\eta_e^{min}$、最长连续关门上限与 CBS 信用界可作快速筛查，但不替代上述净服务检查。下游 AVB 突发按物理路径与上游服务传播，不逐跳重置；有限仿真观察不替代全合同边界。完整预约服务证书尚未实现时列为“待验证”，原型只报告观察的吞吐、积压与时延，不把 2 ms 改软解释为放弃带宽保护。

这些固定合同仍允许普通 AVB 的间隔、突发与帧长模式携带本地 ST 预测信息；预测器不知道其真实相关流名单。

### 4. BE 流模型

Best-Effort（BE）流表示不具有严格实时保证的普通背景业务。

BE 流 $f_l^{BE}$ 定义为

$$
f_l^{BE} = \left\langle P_l, \lambda_l, L_l \right\rangle
$$

其中：

- $P_l$ 表示 BE 流的固定转发路径；
- $\lambda_l$ 表示 BE 的平均到达率或 offered load；
- $L_l$ 表示 BE frame size，设置为

  $$
  \boxed{L_l \in [64, 1518]\text{ B}}
  $$

BE 一个调度窗口内可产生多个 frames，不设硬 deadline 或确定性时隙。正式配置还须登记各口 offered rate $\rho_e^{BE}$、源到达过程族、间隔/ON-OFF/突发参数、长度分布及种子；源流按固定路径派生本口负载。仅给 64–1518 B 不足以定义 BE，当前未给出的发生率/过程参数列为待冻结；不能在方法之间更换生成器或从帧长反推速率。

在 Flex 区域中，BE 仅在：

$$
ST
$$

和满足发送条件的

$$
AVB
$$

均没有占用链路时获得剩余服务机会。

因此其优先级关系为

$$
\boxed{\text{non-preemptive }ST > AVB_{CBS\text{-eligible}} > BE}
$$

由于本文不采用帧抢占机制，当一个 BE 或 AVB frame 已经开始发送时，即使此后 ST 到达，ST 也必须等待当前非抢占帧发送完成，因此 BE/AVB 会产生有限的 residual-frame blocking。

### 5. Flex 服务区域模型

对出口 $e$，本地编译器依据 TT 时间投影后的目标时间坐标形成候选 TT 保护区及保护带：

$$
\tilde G_e=\mathrm{Compiler}_e(\tilde{\mathbf x}_e),\qquad
\mathcal F_e(\tilde G_e)=[0,H)\setminus\left(\mathcal W_e^{TT}(\tilde G_e)\cup\mathcal W_e^{GB}(\tilde G_e)\right).
$$

$\mathcal W_e^{TT}$ 是按最大帧长和栅格预约的保护时间集合，$\mathcal W_e^{GB}$ 是额外保护带集合，两者按编译后的并集计量，不重复计数。实例发送顺序保持固定，但相邻实例是否合并保护、间隙是否开放会随整表目标布局变化。因此 Flex 的段数、各段长度、位置和总量都可变化：

$$
N_e^{Flex},\quad\{|F_{e,j}|\}_j,\quad\{\mathrm{start}(F_{e,j})\}_j,\quad
|\mathcal F_e|=H-|\mathcal W_e^{TT}|-|\mathcal W_e^{GB}|.
$$

固定的是 $H$、链路容量、TT 流集合/周期/释放/路由/截止期以及 AVB 合同，不固定 Flex 总量或 TT 保护区数。固定实例工作量不等于保护带开销固定。主编译规则可在相邻服务机会间隙不超过 12.4 μs 且通过完整验证时合并 protected region；这只合并异步关闭范围，不能默认 Q6 连续开启。合并 TT 保护区可能减少保护带，但若包含空隙，也会增加被保护的空闲时间，二者均须按实际 GCL 统计。保护区内若需等待，Q6 保留必要关闭/再开放子窗口；仅在真实 FIFO 执行仍实现同一计划时才合并 Q6 开门窗口。不能让已排队后继帧利用额外开门时间提前发送。所有子窗口及内部等待对应的门状态都计入实际 GCL 条目。

本地 Actor 可使用当前本出口 Flex 的细粒度编码，或

$$
F_{e,b}=|\mathcal F_e(G_e^{cur})\cap I_b^{rel}|,
$$

其中 $I_b^{rel}=[(b-1)0.5,b\cdot0.5)$ ms。16-bin 可用时长只是摘要，不足以证明某帧有完整发送机会；编译与包级服务仍按 80 ns 栅格和真实发送时间处理。

Flex 内采用非抢占 $ST>AVB_{CBS\text{-eligible}}>BE$。ST 到达时若已有普通帧在发送，仍须等待残帧；每跳单独计入。128 B MAC 按线上 148 B 为 1.184 μs，80 ns 门控下预约完整机会至少 1.20 μs。不能把真实发送时间改写成栅格近似，也不能在帧未完成时关闭其服务机会。

门状态按以下规则编译，GB 阶段不发送 Q6 新帧：

| 区域 | Q7 | Q6 | Q4 | Q0 |
|---|---|---|---|---|
| GB | 关 | 关 | 关 | 关 |
| TT protected region | 关 | 仅具体 TT service sub-window 开，暗间隙关 | 关 | 关 |
| Flex | 开 | 关 | 开，但须 CBS eligible | 开 |

打开门只给队列发送资格，非抢占最高优先级选择发生在链路空闲且完整帧机会足够时；已开始发送的低优先级帧不会被后来 ST 中断。

### 6. 四类业务统一总结

| 类型 | 定义 / 产生方式 | 队列 | 路径与合同 | 在线角色 |
|---|---|---|---|---|
| TT | $\langle P_i,T_i,D_i,L_i,\phi_i\rangle$，每 $T_i$ 释放一帧 | Q6 | 路由固定、$D_i=T_i$、每流长度固定 500/1000 B | 按流表示，整表联合决策与安全准入 |
| ST | $\langle P_g,L_g,D_g\rangle$，每次触发一帧 | Q7 | 路由固定，$D_g=1$ ms 用于性能训练/评测 | 逐出口预测本地队列到达，在 Flex 内发送 |
| AVB | 固定源到达/带宽预约合同，短期可突发 | Q4 | 固定路径，单口 Q4 共用 CBS；2 ms 为软目标 | 包事件进入本地预测；预约服务边界受 Validator 保护 |
| BE | 普通状态/背景流，可多帧 | Q0 | 路由固定，无硬 deadline | 包事件进入本地预测，使用剩余 Flex |

$$
\boxed{\text{本地整张 TT 目标布局}\rightarrow\text{TT 保护区}\rightarrow\text{保护带}\rightarrow\text{本地 Flex}\rightarrow ST/AVB/BE}.
$$

研究假设是：本地预测能够帮助 Actor 把服务机会放在更有用的时刻，再由离线 CTDE 学习端到端回报。它不意味着各口在线联合预测或沿路径对齐预测区间。主工况全部真实 ST 均参与统计，包括未命中、冻结时不可见和跨周期完成的帧；多事件合同越界单列，扩展结果不混入单事件主结论；“接近 TT 的尾部时延”和“代价不增加”都只能作为实验检验目标。

## 本地观测与控制时序架构

区分三个时间概念：GCL 超周期 $H=8$ ms；Set Transformer 的单个 8 ms 历史窗口；每周期第 4 ms 冻结后留给整条控制链的 4 ms 预算。采集持续运行，每个出口预测器与 Actor 每 8 ms 执行一次。

### 1. 固定时序说明：中点冻结、完整控制窗口与边界激活

#### 1.1 第 4 ms 冻结观测，第 8 ms 才激活新表

令 $H=8$ ms、$t_{k+1}=t_k+H$，四个受控出口使用相同的周期与基时间：

$$
C_k=[t_k,t_k+8\text{ ms}),\qquad
t_f=f_k=t_k+4\text{ ms},\qquad
t_{\mathrm{activate},k}=t_{k+1}=t_k+8\text{ ms}.
$$

$f_k$ 是**本轮观测与 Actor 资源输入的冻结点**，不是换表点。预测、Actor 提案及安全执行链在冻结后运行；本轮候选表提前计算完、通过验证或收到 COMMIT，都只表示已经具备准备/激活条件，仍须等待统一周期边界。

记 $G_k$ 为周期 $C_k$ 实际执行的 GCL 组，$\tilde G_{k+1}$ 为本轮编译出的候选组。对同一提交事务：

$$
G^{run}(t)=G_k\quad\forall t\in C_k,\qquad
G_{k+1}=
\begin{cases}
\tilde G_{k+1},&\text{完整硬核验通过且及时完成一致提交},\\
G_k,&\text{任一失败、超时或未取得完整提交依据}.
\end{cases}
$$

因此，$G_k$ 在 $[t_k,t_k+8\text{ ms})$ **全程执行**；$G_{k+1}$ 仅在 $t_k+8$ ms 开始执行。这里的换表指 GCL 版本切换，周期内各门仍按当前表正常开闭。失败时保持当前认证表，不在第 4 ms 换表，也不允许逾期候选在周期中途补装生效；后续换表须重新核验并指定合法周期边界。

#### 1.2 数据面连续运行，控制面使用后半周期

```text
t_k                  f_k=t_k+4 ms                  t_k+8 ms
|--------------------------|--------------------------|
数据面：          整个 C_k 持续执行 G_k、持续采集事件
控制面：                   冻结 → 四口预测 → 上游 Actor
                           → Mapper/前向消息 → 下游 Actor
                           → 汇集/联合投影 → 编译 → 验证
                           → PREPARE / COMMIT → 等待边界
                                                      |
                                             统一激活 G_{k+1}
                                             失败则继续 G_k
```

| 时间（相对 $t_k$） | 控制与采样工作 | 实际执行表与输入边界 |
|---|---|---|
| 0–4 ms | 各出口持续采集本交换机转发至自己的 AVB/BE 包事件 | 数据面执行 $G_k$，合法事件进入本轮历史 |
| 第 4 ms | 冻结本地 32 ms 历史及 TT/Flex/队列/CBS 资源快照 | 只读取 $t^{RX}<f_k$ 的事件；此时尚未产生本轮预测和提案 |
| 4–8 ms | 并行 Local Predictor→上游 Actor/预检查→Mapper/消息→下游 Actor/预检查→联合安全→PREPARE/COMMIT | 全程仍执行 $G_k$；新事件继续入缓冲，但不重算本轮预测/Actor 输入 |
| 第 8 ms | 同一事务具备完整及时提交依据的出口按共同基时间激活 | 成功执行 $G_{k+1}=\tilde G_{k+1}$；失败则 $G_{k+1}=G_k$ |
| 8–16 ms | 按实际表服务并记录本轮目标周期内的 ST 队列到达；第 12 ms 开始下一轮冻结/计算 | 整个 $C_{k+1}$ 执行 $G_{k+1}$；下一张表最早在第 16 ms 激活 |

激活前可刷新的安全摘要只用于确认硬合同与过渡状态，不重新给本轮 Actor 输入冻结后的事件，也不改变本轮 ST 预测。4–8 ms 到达的普通事件留给后续冻结样本；数据面在控制计算期间不暂停。

**超时回退的安全条件。** 4 ms 是控制更新 deadline，不要求每次更新都成功。只有当前表对持续保持仍有证书、流量/状态仍在合同域、影子表可阻止提前生效且事务内各口一致保持旧表时，失败/超时才维持相应硬合同；迟到 COMMIT/过期 baseTime 必须作废。无法保证一致保持时，须用覆盖混合版本的证书或报告系统故障，不能笼统声称“超时天然安全”。在这些条件下，missed update 计入性能与控制失败统计，不把旧表回退伪装成新策略成功。

#### 1.3 4 ms 是含 DAG 依赖的完整控制链预算

冻结后 $[t_k+4,t_k+8)$ ms 内，Topology-v1 的关键路径按层计时：

$$
\begin{aligned}
T_{control}={}&\max_e T_e^{pred}
+\max_{u\in\mathcal L_1}(T_u^{actor}+T_u^{decode}+T_u^{pre})\\
&+\max_{u\in\mathcal L_1}T_u^{mapper}+T_{prop-msg}
+\max_{d\in\mathcal L_2}(T_d^{actor}+T_d^{decode}+T_d^{pre})\\
&+T_{gather}+T_{project}+\max_eT_e^{compile}
+T_{validate}+T_{prepare}+T_{commit}+T_{margin}\le4\text{ ms}.
\end{aligned}
$$

$T^{pred}$ 含冻结快照、特征构建和本地 Predictor；$T^{pre}$ 含已有工具的本口约束检查、必要有界合同修正与候选 GCL 预览；$T^{mapper}$ 含联合 Q7 场景回放与逐边传播封装。$T_{prop-msg}$ 从上游消息发送就绪计至下游接收屏障，含序列化、管理服务机会、最慢必需边、缺失判断与约定超时；不能将多条共享链路消息假定成免费并行。

$T_{gather}$ 含各口候选汇集及联合结果返回，$T_{project}$ 为最终联合 $\Gamma_{time}$。$T^{compile}$ 是最终编译，预览计算不得重复漏计或与最终编译混为一次。$T_{validate}$ 覆盖 C1；$T_{prepare}$ 覆盖安全摘要复核、预装、PREPARED/C2；$T_{commit}$ 覆盖 C3。各项按实际资源计时，不把共享 CPU/GPU 争用下的独立最快耗时相加当成整链保证。

提交截止点 $t_c=t_k+8\text{ ms}-\Delta_{guard}$，保护间隔及同步余量计入 $T_{margin}$。若某条性能消息失效/迟到，下游仅在既定接收截止点执行一次带缺失 mask 的本地决策，不重新推断或补算；若整体来不及在 $t_c$ 前完成提交，按既有整事务回退规则保持旧表。

四口 Predictor 仍可并行，两层 Actor 必须按依赖顺序计入。扩展到更多层时逐层累加 Actor/Decoder/预检查与层间 Mapper/通信的关键路径，并重新验 DAG 和 4 ms 边界；主方案只冻结当前两层。公式是待实测的工程要求，不是已满足 4 ms 的结果。

### 2. 8 ms 滑动历史观测窗口组织机制

$$
W_k^{obs}=[t_f-8\text{ ms},t_f)=[t_k-4\text{ ms},t_k+4\text{ ms}),
$$

$$
\mathcal W_k=\{W_{k-3}^{obs},W_{k-2}^{obs},W_{k-1}^{obs},W_k^{obs}\},
\qquad\bigcup\mathcal W_k=[t_f-32\text{ ms},t_f).
$$

$t_k=0$ 时最近窗口为 $[-4,4)$ ms，下次冻结的最近窗口为 $[4,12)$ ms；窗口首尾相接，32 ms 上下文则与相邻样本重叠 24 ms。启动阶段先预热足够历史，或显式使用缺失/空窗口掩码，不伪造负时间事件。

事件按照 `RX_COMPLETE` 记录精确的本地相对时间。8 ms 是集合聚合跨度，不是采样轮询周期。TT/队列/CBS 资源状态由本地调度接口采集，不混入普通流预测事件。

### 3. 同出口观测域与事件筛选

对 $e=(v,p)$ 和窗口 $W_j$：

$$
X_{e,j}=\{x_n:f_n\in\mathcal O_e,\ t_{n,v}^{RX}\in W_j\},\qquad
\mathcal H_{e,k}^{local}=(X_{e,k-3},X_{e,k-2},X_{e,k-1},X_{e,k}).
$$

一个事件的主输入为

$$
x_n=[\mathrm{FlowID}_n,\tau_n,\Delta t_n,L_n,\mathrm{PCP}_n].
$$

$\tau_n$ 为窗口内相对接收时刻，$\Delta t_n$ 为该出口同 FlowID 的历史包间隔，$L_n$ 为实际帧长。没有前一包时用缺失掩码，不能从未来包反推间隔。仅用静态本地转发表确定该包转发至哪个出口，不将完整路径或 hop index 编码进模型。

筛选同时满足：当前交换机、转发至当前出口、类别为 AVB/BE、已实际完成接收、时间在历史窗口内。不依据 ST 组、相关性标签或 $\Pi_g^{true}$ 删流；一个出口内不同 ST 任务可共享同一事件编码。广播/复制帧若确实转发至多个出口，各出口仅保留自己的转发副本，不能因此读取其他出口队列。

其他出口 packet history、预测与新动作，上游配置版本、完整拓扑、隐藏状态、未来 ST 标签和 Oracle 动作均不进入本地预测器。尚未收到的报文即使源端已经发出，也不可根据理想释放日志提前读取。主设使用本地接收时间；若扩展使用帧内合法源时间戳，必须在该帧实际到达后作为普通包属性读取，并对所有方法统一。

# 第三部分 本地关联预测与动作条件路径传播

## 关联性预测架构与统一数据处理接口

$$
\boxed{\text{出口 }e\text{ 冻结前的全部本地 AVB/BE 事件}\rightarrow
\text{未来 ST 首帧到达本出口队列的 }(q_{g,e,k},\pi_{g,e,k})}.
$$

预测器保留共享 Set Transformer + ModernTCN + 双任务预测头。训练任务为所有 $(g,e)$，参数共享不表示共享观测。

### 1. 结构与数据流

1. **Set Transformer：窗口内多流事件关联。** 对每个出口、每个 8 ms 窗口独立编码变长集合：

   $$
   X_{e,j}=\{x_{e,j,1},\ldots,x_{e,j,N_{e,j}}\},\qquad
   z_{e,j}=\mathrm{SetTransformer}_\psi(X_{e,j})\in\mathbb R^d.
   $$

   事件通过嵌入、注意力交互与池化形成窗口表示。集合不自带顺序，必须保留相对时刻和历史间隔。空窗口使用可学习空集合嵌入与有效掩码。一个窗口中一条流到达多帧，就保留多个事件，不先压成每流一个样本。

2. **ModernTCN：跨窗口演化。**

   $$
   Z_{e,k}=[z_{e,k-3},z_{e,k-2},z_{e,k-1},z_{e,k}]^T\in\mathbb R^{4\times d},
   \quad h_{e,k}=\mathrm{ModernTCN}_\psi(Z_{e,k}).
   $$

   只对本出口 32 ms 历史建模；ModernTCN 的增量由单窗/多窗消融检验，不预设四步序列一定优于更简单模型。

3. **本地发生头与条件时间头。** 目标周期

   $$
   C_{k+1}=[t_k+8\text{ ms},t_k+16\text{ ms})=[t_f+4\text{ ms},t_f+12\text{ ms}),
   $$

   $$
   I_{k+1,b}=[t_k+8\text{ ms}+(b-1)0.5\text{ ms},\ t_k+8\text{ ms}+b\cdot0.5\text{ ms}),\ b=1,\ldots,16.
   $$

   每个 $(g,e)$ 输出 Sigmoid 发生概率 $q_{g,e,k}$ 和 Softmax 条件分布 $\pi_{g,e,k,1:16}$。可加入 ST group 与 egress 的身份嵌入，或用按组预测头；身份只标识任务，不附带路由或其他出口数据。统一写为

   $$
   f_\psi(\mathcal H_{e,k}^{local},ID_g,ID_e)\rightarrow(q_{g,e,k},\pi_{g,e,k}).
   $$

   打包时 $p_{g,e,k,b}=q_{g,e,k}\pi_{g,e,k,b}$、$p_{none}=1-q_{g,e,k}$，共 17 维。主训练采用 BCE 发生损失与仅正样本上的条件时间 CE，不把两个头误写成无条件竞争的 17 类训练协议。

### 2. 单事件监督标签与限次审计

以下普通监督标签仅定义在主合同 $N_{g,e,k+1}\in\{0,1\}$ 内。依第二部分的本地入队量与时间，

$$
y_{g,e,k}=\begin{cases}
b-1,&N_{g,e,k+1}=1\text{ 且 }T_{g,e,k+1}^{Q,first}\in I_{k+1,b},\\
16,&N_{g,e,k+1}=0.
\end{cases}
$$

若 $N_{g,e,k+1}\ge2$，返回独立的 `CONTRACT_VIOLATION` 状态，普通 $y$ 未定义，不映射为首帧或无到达；保存完整运行并单列合同越界，不从该运行中挑出正常周期继续冒充合规主实验。合同内这只是唯一新入队帧位置/无到达的标签编码。令 $E_{g,e,k+1}=\mathbf1\{y_{g,e,k}\ne16\}$，训练损失为

$$
\mathcal L_{pred}=\sum_{(g,e),k}\mathrm{BCE}(E_{g,e,k+1},q_{g,e,k})+
\lambda_t\!\sum_{(g,e),k:E_{g,e,k+1}=1}\mathrm{CE}(y_{g,e,k},\pi_{g,e,k}).
$$

无到达时跳过时间 CE，不能把编码 16 当成条件头的第 17 类。标准化、采样权重与 $\lambda_t$ 只在训练/验证集确定；在自然发生率上检验校准。

**主工况限次与竞争审计。** 六个 $(g,e)$ 分别报告 $N=0,1,\ge2$ 的次数、比例和最小实测到达间隔。主模型只在单事件准入合同内使用，$N\ge2$ 是合同越界，必须保留全部帧并标记该次运行，不静默将其压成首帧标签。主实验准入在测试前根据合同确定，不能根据最终测试轨迹筛掉不利样本；越界轨迹的实际 E2E 性能单列公开。

$(q,\pi)$ 完整描述的仅是“单组在本目标周期新入队 0/1 帧”的离散边际，不给出组间联合共现、格内精确时刻或全部服务需求。$e_{4u}$ 的 B/C、$e_{01}$ 的 A/B 仍可能同时出现。冻结后 4–8 ms 入队但跨到目标周期服务的帧、冻结时已有积压和其他在途帧继续按真实 Q7 FIFO 处理；不能因为每组每周期最多一次就清空这些状态。

同一 ST 帧可在不同出口、不同周期分别形成合法标签；预测按 $(g,e)$ 评价，E2E 按源端唯一帧去重。冻结后才有前兆的正样本不删除，源端触发周期不替代本地入队周期。多事件计数/强度预测为第二阶段，届时需同步修改标签、Actor 需求输入与合同，不把本阶段首帧头直接宣称为多事件模型。

**标签的策略依赖。** E1 使用固定合法网络服务验证本地信息；E2 覆盖合法改表后的本地到达分布。本地预测条件仍仅为本口历史，传播消息作为下游 Actor 的另一条输入，E1.5 单独检验动作条件映射和覆盖。

#### 2.1 预测提前量检验

逐 $(g,e)$ 测量：普通联合变化实际到达当前出口的时刻相对 $t_f$ 的提前量；未来本地 ST 队列到达时间；两者的分布及其与预测性能的关系。任务源端 $T_g^{dec}$ 只能解释生成机制，不能代替本地提前量。弱前兆、冻结时不可见、无前兆子集单报，但主指标覆盖全部样本。

#### 2.2 预测评估：基线、消融与指标

- **指标。** 逐 $(g,e)$ 报 AUPRC、Brier、校准误差；正样本时间头报 NLL、Wasserstein 距离以及覆盖率—平均 bin 集合大小曲线。低发生率任务同时报告正样本数，不只报宏平均。
- **同信息基线。** 训练轨迹边际先验、上周期持续、最佳单流、全本地流的手工事件匹配、手工特征梯度提升及合适的事件序列模型。单流选择与匹配阈值在训练/验证集确定，测试不挑流；基线均不得提前获知 $\Pi_g^{true}$。真实相关流名单和隐藏状态只进入单列的特权上界，不与普通基线混列。
- **多流与多窗消融。** 多流对最佳单流；Set Transformer 对均值池化；4×8 ms 对最后一个 8 ms；ModernTCN 对简单跨窗聚合。检验多流、多窗是否有增量，不预设严格优于关系已经成立。
- **保边际跨流打乱。** 尤其针对 ST-B，在匹配工况的独立任务片段间打乱不同流配对，尽量保持各流间隔/帧长/强度和标签发生率，破坏同步关系。分别报告边际是否保持，以及预测和服务收益是否下降；不把改变单流负载的消融解释为纯关联证据。
- **背景与耦合扫描。** 增加同出口无关流，改变真实联合耦合强度，检验主模型全量普通流输入的鲁棒性。“零任务调制”同时关闭普通流与任务隐藏状态之间的单流和联合调制；只把跨流配对 $\rho_B$ 归零不等于零信息。网络排队还可能留下间接信息，因此检查预测增益是否减少，并追查残余信息来源，不预设全部收益必然等于先验或静态。
- **闭环检验。** E2 用合法改表产生的独立轨迹，检查每出口校准和 bin 偏移。0.5 ms 是否足够由 E0 的精确时刻/16-bin Oracle 对照及同控制器服务收益判断，不仅看分类准确率。

### 3. 统一数据处理接口规范（`build_observation`）

离线和在线使用同一筛选与窗口接口。以下代码为数据接口规范，不从全网日志直接提取特征：

```python
def build_observation(events, switch_id, egress_port, freeze_ns,
                      history_ns=32_000_000, window_ns=8_000_000):
    """events 可来自审计日志；只返回当前交换机同一转发出口的 AVB/BE。

    事件字段：switch_id, egress_port, traffic_class, event_type,
    rx_time_ns, flow_id, length, pcp；不包含真实相关流名单或未来标签。
    """
    if history_ns <= 0 or window_ns <= 0 or history_ns % window_ns:
        raise ValueError("history must contain complete positive windows")
    start_ns = freeze_ns - history_ns
    windows = [[] for _ in range(history_ns // window_ns)]
    for event in events:
        if event.switch_id != switch_id or event.egress_port != egress_port:
            continue
        if event.traffic_class not in {"AVB", "BE"}:
            continue
        if event.event_type != "RX_COMPLETE":
            continue
        if not (start_ns <= event.rx_time_ns < freeze_ns):
            continue
        idx = (event.rx_time_ns - start_ns) // window_ns
        windows[idx].append(event)
    return windows
```

后续特征层只提取白名单字段：FlowID、窗口相对 RX 时间、因果包间隔、真实长度和 PCP。接口中的出口标识用于筛选，不构造路径向量。禁止用理想源释放日志替代本地 `RX_COMPLETE`，也不依据 ST 真值分组过滤输入。超出运行容量时的截断/采样规则必须只基于本地已见事件、训练在线一致，并报告丢弃率。

## 离线数据生成与在线推断的严格界限

必须建立“仿真器记录了什么”与“模型训练时允许看到什么”的明确分界，从根本上杜绝未来信息泄漏。

### 1. 核心准则：离线连续记录，样本严格裁剪

1. **离线数据生成（完整连续轨迹）**：
   运行 TSN 离线仿真时，连续记录完整的物理事件流：

   $$
   \mathcal L^{log} = \{x_1, x_2, \dots, x_N\}
   $$

   可以连续仿真完整任务轨迹，记录各交换机、各转发出口的 AVB/BE 接收事件以及独立的 ST 触发/入队/完成日志。日志物理上可以集中保存，模型输入仍按出口隔离。**离线生成数据时完全无需在每个周期的第 4 ms 暂停仿真器**。

2. **离线样本构建（严格模拟在线冻结截断）**：
   在从完整轨迹 $\mathcal L^{log}$ 中构建监督训练样本时，每个样本都必须绑定一个明确的冻结时刻 $t_f$。对于样本 $k$：

   $$
   \boxed{ x_i \in \mathcal{H}_{e,k}^{local} \Longrightarrow f_i\in\mathcal O_e,\ t_i^{RX} < t_f }
   $$

   典型训练样本切分对应关系如下表所示：

   | 样本序号 | 冻结时刻 $t_f$ | 模型可见的 8 ms 滑动观测窗口 $W_k^{\mathrm{obs}}$ | 完整的 32 ms 历史范围 | ST 标签对应服务周期 $C_{k+1}$ |
   |---|---|---|---|---|
   | **样本 1** | 4 ms | $[-4, 4)\text{ ms}$ | $[-28, 4)\text{ ms}$ | $[8, 16)\text{ ms}$ |
   | **样本 2** | 12 ms | $[4, 12)\text{ ms}$ | $[-20, 12)\text{ ms}$ | $[16, 24)\text{ ms}$ |
   | **样本 3** | 20 ms | $[12, 20)\text{ ms}$ | $[-12, 20)\text{ ms}$ | $[24, 32)\text{ ms}$ |
   | **样本 4** | 28 ms | $[20, 28)\text{ ms}$ | $[-4, 28)\text{ ms}$ | $[32, 40)\text{ ms}$ |

以样本 1 为例：尽管离线仿真器中已经记录了 4–8 ms 的所有报文，但在构建样本 1 的特征输入时，**严禁使用任何 $t^{rx} \ge 4\text{ ms}$ 的报文**！4–8 ms 期间的报文并没有被浪费，它将在样本 2（12 ms 冻结）中作为合法的历史数据参与输入。

### 2. 严禁事项：为何离线训练不可使用当前完整 0–8 ms？

如果在离线训练中，错误地将当前周期 $[0, 8)\text{ ms}$ 的完整报文作为输入，来预测下一周期 $[8, 16)\text{ ms}$ 的 ST：

- 模型实际上吸收了 4–8 ms 期间的到达前兆；
- 但在线部署时，系统在第 4 ms 必须冻结并花费 4 ms 运行 DRL 调度与编译；
- 这将导致**严重的未来信息泄漏（Future Information Leakage）**与**训练-部署信息不一致（Train-Test Inconsistency）**，严重虚高离线预测指标，使在线部署彻底失效。

### 3. 离线训练与在线推断的系统对比

| 比较维度 | 离线训练阶段 | 在线推断与运行阶段 |
|---|---|---|
| **原始事件采集** | 连续记录完整长周期的网络轨迹 | 持续捕获真实数据包入端事件 |
| **输入特征构建** | 依各样本冻结时刻 $t_f$ 严格前向裁剪 | 实时截取当前冻结时刻 $t_f$ 之前的历史 |
| **Set Transformer** | 仅使用 $t_f$ 之前的历史数据 | 仅使用 $t_f$ 之前的历史数据 |
| **ModernTCN** | 输入 $t_f$ 之前连续 4 个 8 ms 窗口 | 输入 $t_f$ 之前连续 4 个 8 ms 窗口 |
| **ST 首帧到达当前出口队列** | 用于生成 $q$ 与 16 格的监督标签。不是源端产生概率 | 各出口在线由模型输出 $q_{g,e,k}$ 与 $\pi_{g,e,k}$ |
| **参数更新与优化** | 执行反向传播与多 Epoch 梯度下降 | 保持参数冻结，仅执行快速前向推断 |
| **时间耗时约束** | 离线运行，不受 4 ms 计算预算限制 | **必须严格在 4 ms 预算内完成推断与后续控制链** |

### 4. 实施层面的三大关键警示

1. **报文到达采样与模型推断严格解耦**：
   数据面每到达一个报文，网卡/交换机仅以最小开销将其追加写入事件环形缓冲区（Ring Buffer）；**绝对不是每来一个包就执行一次 Set Transformer + ModernTCN**。模型推断在超周期第 4 ms 仅被周期性触发一次。
2. **按独立轨迹划分数据集，严防样本重叠泄漏**：
   由于连续样本之间的 32 ms 历史窗口存在 24 ms 的高度重叠，**严禁将相邻冻结样本随机打乱划分至训练集与测试集**！必须按照独立的工业任务实例（Task Instance）或完全独立的连续长仿真轨迹进行 Train / Val / Test 隔离划分。
3. **4 ms 是全控制链预算，非推断独占**：
   统一采用第二部分时序说明中的 $T_{\mathrm{control}}\le4$ ms：从 $f_k=t_k+4$ ms 冻结开始，计入预测、Actor、汇集、投影、编译、验证、预装、准备、提交与余量；一致提交须在 $t_c$ 前完成，新表仅在 $t_k+8$ ms 生效。共享 CPU 的争用和管理网络传输也计入预算。装不上或提交不齐，事务内保持原表。

## 动作条件路径传播：Service Mapper 与消息协议

### P.1 固定路由消息图与分层执行

由部署路由构建带组别标签的出口消息图 $\mathcal D_{msg}=(\mathcal E_c,\mathcal A_{msg})$。仅当 $u,d$ 是组 $g$ 固定路径上相邻的受控出口，且中间固定服务段有已声明的映射，才允许边 $(g,u,d)$。Topology-v1 为

$$
\mathcal A_{msg}=\{(A,e_{3u},e_{01}),(B,e_{4u},e_{01}),(C,e_{4u},e_{02})\}.
$$

部署时检查全部消息边的并图无环，冻结拓扑排序、父边槽位和接收截止点。单条物理路径无环并不自动保证多条路径合并后的出口消息图无环；不能将本方法推广为任意固定路由均可按此排序。当前两层图已明确，扩展变体须单独准入。

下游的 local prediction 在同一冻结点独立计算完毕；等候的只是上游本轮动作条件消息。收到消息不触发 Predictor 重算。下游只执行一次 Actor，最终 Safety 之后也不回传性能消息。

### P.2 本地预候选、服务映射与逐跳时刻

已有 Decoder/局部预检查形成 $G^{pre}_{u,k}$，其哈希和候选版本随消息绑定。定义

$$
\{\mu^{TX}_{g,u,k}\}_{g\in\mathcal G_u}
=\mathcal S_u\!\left(\{p^{loc}_{g,u,k}\}_g,G^{cur}_{u,k},G^{pre}_{u,k},
\eta^{local}_{u,k};\mathcal C^{map}_u\right).
$$

$\mu^{TX}$ 表示本口 ST **发送完成**时刻的分布/区间；$\mathcal S_u$ 为固定的队列与门控回放算子，无可训练参数，不优化 TT。$\mathcal C^{map}_u$ 冻结场景规则、bin 内近似、残帧/未知到达包络、并发平局、计算上限与截尾规则。它与硬安全合同分开版本化，其近似不授予安全保证。

对一个具体场景中按真实到达/FIFO 顺序排好的 Q7 帧 $j$，记 $a_j$ 为本口就绪时刻，$c_{j-1}$ 为前一 Q7 帧完成时刻，$\tau_j=8(L_{g(j)}+20)/C_u$。发送起点要求

$$
b_j=\operatorname{NextFit}_{G_u^{map},\omega}
\left(\max\{a_j,c_{j-1}\},\tau_j\right),\qquad c_j=b_j+\tau_j.
$$

`NextFit` 同时检查链路空闲、Q7 队头、完整帧能落入 Flex 以及已启动 AVB/BE/管理帧的非抢占残余；$\omega$ 是该场景的因果到达/占用实现。它不能简化为“取最近 Flex 起点”，也不能让后来的小 ST 绕过发不下的 FIFO 队头。回放中

$$
G_u^{map}(t)=\begin{cases}
G_u^{cur}(t),&f_k\le t<t_k+8\text{ ms},\\
G_u^{pre}(t),&t_k+8\text{ ms}\le t<t_k+16\text{ ms}.
\end{cases}
$$

候选在第 8 ms 之前没有服务作用；第 16 ms 后的表尚未知，未完成质量须标记为右截尾/窗口外，不假定下一轮仍用本候选来伪造精确时刻。

对相邻出口的 store-and-forward 物理段，

$$
t^Q_{g,J,d}=c^{TX}_{g,J,u}+d^{prop}_{u,d}+d^{proc}_d,
\qquad \mu^Q_{g,u\to d,k}=(\mathcal P_{u\to d})_\#\mu^{TX}_{g,u,k}.
$$

其中 $c^{TX}$ 已含本跳序列化，不再重复加 ST 发送时长；处理主值按已有模型的 2 μs，传播参数依配置。若两受控出口间含额外固定跳，$\mathcal P$ 必须包含其实际固定服务/排队映射，不能用常数平移省略等待。

### P.3 多组竞争与概率近似

$e_{4u}$ 的 B/C 必须进入同一次 Q7 回放：

$$
\mathcal S_{4u}(p^{loc}_{B,4u},p^{loc}_{C,4u},G^{pre}_{4u},\eta^{local}_{4u})
\to(\mu^{TX}_{B,4u},\mu^{TX}_{C,4u}).
$$

不能各自获得同一个首个 Flex；$e_{01}$ 的 A/B 在下游服务中也按真实 Q7 竞争。固定平局顺序使用到达时刻、组/源帧标识等已登记规则，与实际仿真器一致。冻结时已有 Q7 积压必须参与；低优先级非抢占残帧不能因 ST 优先级最高而消失。

**边际输出不识别联合分布。** $p^{loc}_{g,u}$ 仅给各组发生/时间边际。首版 Mapper 使用测试前冻结的有限加权场景集 $\Omega_u=\{(\omega_r,w_r)\}_{r=1}^{R_u}$：从各组边际按声明的独立组假设构造组合，格内用固定均匀求积或固定区间传播，统一联合回放；$R_u$、权重归一、求积位置和截断上限入配置。该独立假设只用于概率场景构造，**不表示 Q7 服务独立**。确定性求积/固定公共样本保证同输入同输出，不新增联合预测器或场景生成网络。

独立边际、格内均匀和未来低优先级残帧的包络处理都属于近似，不能从 $q,\pi$ 推出它们真实成立。E1.5 分别报告组间共现/先后次序条件误差、格内时刻误差及残帧压力结果，并以允许边际下的同步/错峰极端组合做敏感性。若只使用区间界，报告覆盖和宽度；无依据不将区间当成校准概率。

### P.4 跨周期覆盖与消息有效性

Local Predictor 的主输出只覆盖 $C_{k+1}=[t_k+8,t_k+16)$ 的本口新入队。这不足以自动构造完整的下游目标周期到达分布：

- 冻结时已排队的 ST、已知在途帧可能在目标周期到达下游。
- $[f_k,t_k+8)$ 新入队的 ST 可能跨到目标周期服务，该时段不在本轮预测头覆盖内。
- 目标周期末入队者可能在下一周期才到下游；上游该周期无到达也不代表下游该周期无到达。

因此 $\eta^{local}_u$ 只由冻结时已知 Q7/残帧/合法本地在途摘要、已有硬到达包络和当前表下的因果外推构成。未知的冻结→激活到达以及未知残帧用事先声明的合同区间/压力场景包住，不能读取冻结后的真实日志，也不为此增加预测头。包络仅提供可能范围，不能自动提供发生概率。

只有在覆盖和联合场景近似已声明、且场景中下游目标周期满足每组 0/1 入队时，才从完整场景回放得到

$$
\begin{aligned}
p^{prop}_{g,d,k,b}&=\sum_r w_r\mathbf1\{N^{(r)}_{g,d,k+1}=1,
\ t^{Q,(r)}_{g,d}\in I_{k+1,b}\},\\
q^{prop}_{g,d,k}&=\sum_{b=1}^{16}p^{prop}_{g,d,k,b},\qquad
\pi^{prop}_{g,d,k,b}=p^{prop}_{g,d,k,b}/q^{prop}_{g,d,k},\\
p^{prop}_{g,d,k,none}&=\sum_rw_r\mathbf1\{N^{(r)}_{g,d,k+1}=0\}=1-q^{prop}_{g,d,k}.
\end{aligned}
$$

$q^{prop}=0$ 时条件分布未定义，编码为零槽并置 occurrence mask。移动出窗口的质量保留在窗口外账本并按目标窗口无到达处理，不能截断后将窗口内质量重新归一为必达；跨入窗口的已知 carry-in 也必须计入。不存在 $q^{prop}_{g,d}=q^{loc}_{g,u}$ 的普遍等式。

若未知前缀/积压使目标概率不可识别，不给未建模部分擅配概率。仍可在同一条消息中发送 `mode=INTERVAL` 的保守到达信息：在合同允许的未知实现上，对每个目标 bin 的事件概率取下/上界，并给出发生概率区间和覆盖说明。该界针对已声明的本地概率输入及物理包络，不保证本地预测本身正确；各 bin 上界不要求和为一。有限场景的最小/最大值无全包络覆盖证据时只称压力结果，不能冒充这些界。无法得到有效分布或区间、场景违反单事件合同、预算耗尽及未知服务段时置 `valid=0`。

消息 `mode=PROB` 使用上述 $q^{prop},\pi^{prop}$，`mode=INTERVAL` 使用固定长度的概率界槽且屏蔽点概率槽；下游在同一 Actor 输入中保留模式和缺失 mask。两种编码均属于同一 propagated arrival message，不增加网络或通信轮次。`valid=1` 只表示通过该模式的覆盖/接口检查，不表示真实概率精确或硬安全认证通过。E1.5 分别报告两种模式的占比、概率校准或区间覆盖/宽度、全部消息失效率及窗口外质量。若信息有效率过低，先收窄传播价值结论，不添加预测网络补洞。

区间模式可按固定加权场景和未识别实现集合 $\Xi_r$ 定义：令 $h_b(\omega_r,\xi)$ 为“该场景下目标 bin 有该组唯一到达”的指示量，则

$$
\underline p_b=\sum_rw_r\inf_{\xi\in\Xi_r}h_b(\omega_r,\xi),\qquad
\overline p_b=\sum_rw_r\sup_{\xi\in\Xi_r}h_b(\omega_r,\xi).
$$

将 $h_b$ 换成目标周期内有唯一到达的指示量得到 $[\underline q,\overline q]$，不把各 bin 的上下界分别归一化为 Softmax。实现可用经验证的保守服务区间外包这些极值，不能用只搜索到的样本极值代替全域界；预算耗尽时返回未知/无效状态。这一映射不搜索 TT 动作，也不增加预测头。

### P.5 route-constrained propagated arrival message

一个组/固定边/决策轮至多发送一条最终性能消息：

$$
m_{g,u\to d,k}=(k,g,u,d,\mathrm{horizon},\mathrm{bin\_spec},
\mathrm{mode},q^{prop},\boldsymbol\pi^{prop},\mathrm{bounds},\mathrm{valid},\mathrm{coverage},
\mathrm{candidate\_id},\mathrm{config\_hash},\mathrm{mapper\_version}).
$$

`candidate_id` 绑定上游 $\mathbf x^{pre}_u/G^{pre}_u$ 哈希、本轮当前表版本和激活点；`bounds` 是 INTERVAL 模式的发生/逐 bin 概率下上界，未用槽固定填充并掩码；`coverage` 是已覆盖、窗口外/右截尾及近似状态的固定元数据。字段精度、最大字节数与网关校验在计时前冻结。可选 confidence 仅取离线验证集冻结的校准表/区间，不新增置信网络，不能把一个任意常数当成可验证置信度。

| 通道 | 允许字段 | 接收者 / 用途 |
|---|---|---|
| Predictive coordination | 本节紧凑到达分布、固定边/周期、版本与有效性 | 固定子边的下游 Actor 性能决策 |
| Contract safety | TT 预候选/当前表、TT/AVB 合同、过渡摘要、候选哈希/版本、baseTime、准备/提交状态 | 安全链核合同与一致提交 |

性能通道不携带 32 ms packet history、Set Transformer embedding、ModernTCN hidden state、整口队列/CBS、完整 GCL、Critic state 或全网状态。安全通道不夹带预测概率。路由/版本字段由消息网关检查，Actor 只见固定槽位的分布、coverage 和 valid/missing mask，不把哈希或路由串作为学习特征。

消息周期、目标窗口、bin、固定边或版本不匹配时作无效处理；丢失、迟到、Mapper 失败、截尾超过已声明范围也作缺失槽。下游在接收截止点用 **自己的本地预测 + 已收到的有效消息 + 固定缺失编码** 执行一次 Actor，不取下一周期或旧候选消息代替，不以 $q=0$ 伪装“确认无到达”。训练/测试采用同一失效模型和接收屏障；性能通道不请求重发/反向协商。

### P.6 逐跳本地修正的准确含义

$$
o^{actor}_{d,k}=[z^{pred}_{d,k},\{p^{loc}_{g,d,k}\}_g,
\{p^{prop}_{g,d,k},bounds,mode,valid,coverage\}_{\mathrm{pa}(d)},resource_{d,k}].
$$

本地预测与传播消息是同一实际到达的相关证据，不使用 $p^{fused}\propto p^{loc}p^{prop}$，也不将两者需求相加计作两帧。Actor 通过已有策略网络学习在这些输入下提出一个动作；“local correction”指根据两路证据修正**本口决策**，不声称生成了一个新的校准融合后验。

主 Topology-v1 的下游已是最后一层，因此不存在继续向第三层输出的接口承诺。若另设多层 DAG 变体，必须明确后续 Mapper 如何使用本层已有证据及跨周期覆盖，并重新验证；不能把 Actor 的修正自动当成新的预测分布。这项扩展不进入当前主设。

### P.7 单轮在线算法的实现接口

```text
输入：冻结的各口本地历史/资源、当前认证表、固定合同/DAG/消息截止点
并行：各 e 计算 p_loc[e]，构建不含本轮消息的 o_base[e]
并行：各 u∈L1 采样/输出一次 δ[u]
      x_hat[u] ← Decoder(δ[u]; x_cur[u])
      x_pre[u], G_pre[u] ← 已有工具的局部预检查/候选预览
      local precheck 失败则预候选采用当前认证表，记录失败状态
      联合回放本口全部 ST → 沿固定子边各发送一条版本绑定的消息
屏障：在既定接收截止点封闭本轮消息槽，迟到/无效边置固定缺失 mask
并行：各 d∈L2 用 o_base[d] 和有效消息采样/输出一次 δ[d]
      Decoder/局部预检查生成 x_pre[d]，保存原始动作和已用消息
联合：Γ_time(x_pre; contracts) → 最终 Compiler/Validator → C2/C3
      只有完整及时提交才在 t_k+8 ms 激活；失败整事务保持当前表
输出：δ、x_hat、x_pre、已用消息、x_exec/版本/耗时/失败记录
离线：记录真实 E2E 回报，重算传播一致性；不回填本轮输入
```

上述“并行”均服从实际设备资源，所有阶段计入同一 4 ms。算法只有一次上游提案、一次前向传播和一次下游提案；安全求解器内部有界 repair 属于合同核验实现，不构成性能层的多轮重规划。

# 第四部分 出口局部可观测下的端到端性能优化与合同安全

## 本地性能决策与运行规则

### 0. 从本地信息到 E2E 目标：模型与理论边界

#### 0.1 端到端时延来自实际整条路径

对唯一 ST 源帧 $J$，以完整物理路径上的各排队点记

$$
d_J^{E2E}=c_J^{dest}-r_J^{src}=d_J^{phys}+\sum_{e\in P_{g(J)}}W_{J,e},\qquad
W_{J,e}=t_{J,e}^{TX}-t_{J,e}^{Q}.
$$

$d_J^{phys}$ 只包含该帧的发送、传播、固定处理等非排队项；未受控端口仍可能随到达相位变化的等待也在求和中，不能因为其 GCL 固定就并入常数。源端若另有释放后排队，同样纳入完整记录。

在同帧、固定物理项下，所有跳的**实际等待总和**下降才推出 E2E 下降。各口分别最小化基于本地预测的等待代理，并不保证联合运行后的等待总和下降：上游改变下游到达，其他 Actors 同时改表，多组竞争及安全修正也改变实际服务。因此主目标使用真实 E2E，逐跳等待仅用于解释收益与瓶颈。

#### 0.2 带 DAG 条件策略与固定合同执行映射的合作过程

沿用合作 Dec-POMDP 的环境、局部观测和团队回报框架（[原始框架](https://people.cs.umass.edu/~immerman/pub/bgiz.pdf)），增加固定 DAG 内的有序通信/动作微步骤；这是一轮内部因果条件执行的具体建模，不称为四个无通信 Actor 的乘积策略。

$$
\mathfrak M_{\mathcal C,\mathcal D_{msg}}=\langle\mathcal E_c,\mathcal S,\{\mathcal A_e\},
P_{\mathcal C,\mathcal D_{msg}},\{\mathcal O_e^{obs}\},\mathcal Z,R,\rho_0,K_{ep},\gamma\rangle.
$$

$s_k$ 包含任务/源恢复计时、源生成状态、FIFO 帧身份和年龄、在途与链路残余占用、CBS、当前/待激活版本、提交状态、各口历史缓冲以及 episode/cohort/miss 账本。$\rho_0$ 是预热后的初态，$K_{ep}$ 是固定有限步数；观测压缩不保证充分 Markov。消息微步骤的候选版本、已收消息槽和截止状态属于轮内控制状态。

冻结点先得到各口不含本轮消息的 $o^{base}_{e,k}$。上游动作先采样，消息由该动作和冻结的输入确定：

$$
\boldsymbol\delta_{u,k}\sim\pi_\theta(\cdot\mid o^{base}_{u,k}),\qquad
\mathbf m_k=M(\boldsymbol\delta_{\mathcal L_1,k},\mathbf o^{base}_k;
\mathcal C^{map},\xi^{msg}_k).
$$

$M$ 包含 Decoder、已有工具的局部预检查、Mapper 与固定边传输；$\xi^{msg}$ 表示实际延迟/丢失/截止状态。确定性算子本身无学习参数；共享 $\theta$ 不允许跨口隐藏状态共享。下游输入 $o^{actor}_{d,k}=[o^{base}_{d,k},\mathbf m_{\mathrm{pa}(d)\to d,k}]$，无效边按缺失编码。

给定这次消息交付实现，联合条件策略为

$$
\boxed{\Pi_\theta(\boldsymbol\delta_k\mid\mathbf o^{base}_k,\xi^{msg}_k)=
\prod_{u\in\mathcal L_1}\pi_\theta(\boldsymbol\delta_{u,k}\mid o^{base}_{u,k})
\prod_{d\in\mathcal L_2}\pi_\theta(\boldsymbol\delta_{d,k}\mid
o^{base}_{d,k},\mathbf m_{\mathrm{pa}(d)\to d,k}(\boldsymbol\delta_{\mathcal L_1,k}))}.
$$

这是一种 **decentralized but causally conditioned execution**。同层可并行，跨层依赖不能删掉；所有本轮动作/消息是轮内先后事件，不额外创造多个 8 ms 环境 step。

固定执行映射仍为

$$
(\mathbf x_k^{exec},G_{k+1},v_{k+1},status_k)
=\Gamma_{safe}(s_k^{safe},\mathbf x_k^{pre},\mathcal C_{fixed},\xi_k^{ctrl}),
$$

$$
s_{k+1}\sim P_{\mathcal C,\mathcal D_{msg}}(\cdot\mid s_k,\boldsymbol\delta_k),\qquad
J(\theta)=\mathbb E\left[\sum_{k=0}^{K_{ep}-1}\gamma^kR_k\right].
$$

$s^{safe}$、$\xi^{ctrl}$ 分别包含安全状态和真实耗时/故障/允许的安全摘要刷新；$P$ 吸收消息失效、解码、预检查、最终安全修正、编译/提交及回退。Safety 只收 TT 候选与合同；最终执行一般不能按出口独立分解。消息路由固定且本轮只前向一次，未获得完整硬检查和及时提交仍不能激活。

#### 0.3 冻结到冻结的 RL step 与边界激活

训练转移区间与 GCL 服务周期不同：

$$
B_k=[f_k,f_{k+1})=[t_k+4,t_k+12)\text{ ms},\qquad
G^{run}(t)=
\begin{cases}
G_k,&t\in[t_k+4,t_k+8)\text{ ms},\\
G_{k+1},&t\in[t_k+8,t_k+12)\text{ ms}.
\end{cases}
$$

其中 $G_{k+1}$ 是第 8 ms 边界实际生效的表，失败时等于 $G_k$。这条分段式仅为训练账本划分，不表示在第 4 ms 换表；完整服务周期 $C_k$ 始终由 $G_k$ 执行。预测标签仍覆盖 $C_{k+1}=[t_k+8,t_k+16)$ ms，不把它与 $B_k$ 混用。

从 $f_k$ 到边界的 4 ms 内，本轮动作尚未生效，网络按旧表继续运行。冻结状态、提案版本、共同激活点、实际提交状态和每跳生效版本共同记录；团队回报按真实时间积分与事件结算，跨周期结果继续保留，不回溯改写冻结到激活之间的执行记录，也不把整条 ST 归给最后一跳、最后一个周期或未激活表。固定路径帮助离线追踪这些结果，不进入在线 Actor 的路径特征。

#### 0.4 能优化期望性能，不能消除信息限制

若两个环境状态给某出口完全相同的完整 Actor 输入（本地证据、允许的父边消息、mask 与本地隐藏状态），却需要不同性能提案才能分别达到状态最优，该口策略只能给出相同条件动作分布。相同本地历史而父边消息不同的状态允许产生不同动作；传播正是增加了这一可用条件。离线训练不能创造完整允许输入中不存在的信息，集中最优也不由该架构自动保证。

因此本文定位为 **end-to-end-aware local policies with egress-local sensing and route-constrained causal communication**。在相同合同执行映射和动作权限下，最优 DAG 条件策略类不优于包含它的集中/特权策略类；但**实际求得的** JointScheduleOracle 未必最优，不能强写其每条测试曲线必胜。安全映射也可修正不同提案，故信息限制讨论针对包含同一 Gamma 的整体策略类，不忽略合同协调已提供的作用。

主方法每 8 ms 对四个出口各运行一次 Predictor 和一次 Actor。Actor 按 DAG 层次使用本地需求、有效父边消息及本口 TT/Flex，一次输出整表 $a_e=\boldsymbol\delta_e$；$\delta_e=\mathbf0$ 解码为当前表 KEEP 提案，最终执行仍可能被合同修正。没有在线全路径 ST 服务证明，也不要求某个预测概率越过阈值才运行 Actor。

低概率跳过推理等计算节省机制只能列为后续部署消融，其输入仍限于本地信息与允许的父边消息，不能替代本方法的每周期决策。主方法不以 ST 全路径截止期判断是否换表。硬安全失败、控制超时、主动保持参考及成功提交相同表是不同情形，分别统计。

### 1. 本出口服务表征

对当前出口队列就绪时刻 $t^Q$ 与本地 GCL $G_e$，定义

$$
R_{g,e}^{local}(t^Q,G_e)=c_{g,e}^{TX}(t^Q,G_e)-t^Q,
$$

即从本口入队到本口发送完成的局部响应。它不是端到端时延，不能据此独立证明 $D_g$。最早发送起点要求：已到达、排到 Q7 队头、无正在发送的非抢占残帧，且门开剩余时间足以发完整帧。

若为规则基线或离线诊断按 bin 汇总，可定义

$$
\bar R_{g,e}(b,G_e)=\sup_{t^Q\in I_{k+1,b}}R_{g,e}^{local}(t^Q,G_e)
$$

并声明固定的本地积压/竞争假设；$q_{g,e}\sum_b\pi_{g,e,b}\bar R_{g,e}(b,G_e)$ 只是按概率加权的格内局部最坏响应，不是真实期望，更不是全路径上界。该量不上传给在线安全协调层，也不作为在线安全协调层的性能安装准入。

同一出口多组唯一新入队帧的边际预测不描述联合共现；同组跨周期积压、其他组帧及主合同越界帧仍按实际 Q7 FIFO 时间轴服务。两帧之间若遇关门，第二帧等待可能长于一帧发送时间，不能用 $K\tau$ 替代。规则基线若用本地训练数据的联合场景或保守聚合，应明确这一近似，不能读取未来真实到达。

### 2. 预测分格与物理服务边界

0.5 ms 仅表示 ST 到达不确定性；门控时刻和整帧发送仍按实际帧长与 80 ns 栅格检查。E0 的主参考 FixedOrderJointScheduleOracle 在固定源端外生轨迹下，集中搜索合法的 TT 目标时间坐标，并逐候选回放实际网络。它可使用未来随机实现与源释放，因此是特权诊断，不属于在线安全协调层。若未证明全局最优，只称“受限 Oracle 参考”，不称严格性能上界。

下游队列到达会随候选上游 TT 整表时间布局变化。主 Oracle 必须在相同源释放、任务状态和随机种子的外生轨迹下重新计算各口到达，不能把静态表测得的下游时间固定为所有候选的真值。

**分辨率诊断单独控制外部到达。** 为区分精确时刻与 16-bin 表示的影响，在固定上游合法表、只调整一个出口的场景中比较以下两个变体；二者的 TT 时间权限和硬合同完全一致，当前出口的入队事件不随其本地动作改变：

| 单出口诊断变体 | 决策器可用信息 | 作用 |
|---|---|---|
| Oracle-Exact-Time | 相同外部 ST 入队轨迹的精确时刻 | 检验精确时刻下的可改善空间 |
| Oracle-16-Bin | 同一轨迹的发生与首帧所在 0.5 ms bin | 检验预定格内保守服务规则的损失 |

16-bin 决策器的候选选择只能用格区间及测试前固定的保守规则；精确时间仅由隔离评测器用于最终报告，不将评分反馈给搜索。这个单出口诊断不冒充四口闭环的纯信息上界。四口闭环的实际量化影响仍由 E2 用同一控制器验证。

精确变体有改善而 16-bin 无改善时，才在验证阶段研究 0.25 ms；同时检查保守规则、求解质量和动作权限，不能把差距全部归因于预测网络。主 JointScheduleOracle 与强静态也无可重复差距时，停止学习控制训练并诊断合同、基线和场景，不盲目增加模型。

#### PerfectLocalInfo：局部未来到达的特权诊断

补充 **PerfectLocalInfo-16Bin**，但不把未来真值当成部署时的本地可用信息。先选一个受控出口，固定其上游及其他口实际 GCL/整表坐标与外生源轨迹，只允许该口提出整表动作；时间投影也固定其余口的坐标，不为本口修正而改变其他口布局。须确认其入队不受该动作或反馈流控反向影响。此时隔离评测器可在冻结点提供下一目标周期的本口真实发生标记与 one-hot bin；无到达时以 $q=0,\pi=\mathbf0$ 编码，不额外提供真实发生 mask。它与 Oracle-Exact-Time 不同，仍只提供 0.5 ms 信息。

低成本版本使用同一 Rule，学习诊断使用同一 MAPPO Actor/训练协议；每次配对只改变“预测的 $q,\pi$”与“真实的 $q,\pi$”，两边都去掉 $z^{pred}$，嵌入填相同零槽，共同 mask 只表示静态任务/填充，不能由真实发生标签生成或传给预测分支。保持相同局部资源、动作权限、安全层、E2E 回报与预算，其余口均维持同一固定实际表，停用其 Actor 更新与动作，避免共享权重更新连带改动。诊断不计入九类主比较，也不与四口主方法混画成一条必然单调的性能阶梯。

在这一受控条件下，Prediction→PerfectLocalInfo 的差值衡量改善到达信息的经验潜力，仍含训练/求解误差，不能称严格预测误差损失或性能上界。PerfectLocalInfo→JointScheduleOracle 若要比较，须将 Oracle 同样限制为该单出口权限；差值也不能单独归因为局部可观测性。

四口 DAG 闭环中，下游真值依赖上游本轮动作；不得先用静态表生成“真实本地标签”再交给四个 Actor，或用本轮执行后的到达回填本轮输入。未实现无循环、无事后泄漏的特权接口前，不运行四口 PerfectLocalInfo+MAPPO。单出口诊断失败只触发信息、规则、动作空间与训练质量检查，不能证明四口局部方案不可行；实际可用信息仍由 E1 的因果本地历史与 E2 闭环结果检验。

## 优化目标与两层安全实现

### 1. 性能目标：离线训练，在线本地执行

主实验优化同一有限任务 episode 的五项累计团队成本：

$$
\min_\theta\ \mathbb E_{\Pi_\theta,P_{\mathcal C}}\left[\sum_{k=0}^{K_{ep}-1}
\left(\lambda_D C_{ST-delay,k}+\lambda_M C_{ST-miss,k}
+\lambda_A C_{AVB,k}+\lambda_m C_{reconf,k}+\lambda_p C_{projection,k}\right)\right].
$$

主设置 $\gamma=1$，与第五部分的完整 episode E2E 核算对应；若改为折扣目标，必须单列并说明其不再严格等价于未折扣时延总成本。ST 项作用于全部源帧的端到端过程，而不是每口各自最小化自己的等待。团队回报对全部 Actors 共享，安全层作为相同环境接口参与训练和测试。

第五部分明确逐 step 成本、跨周期账本及终止处理。归一化常数和五项权重在训练/验证集冻结，不使用当前预测正样本数或已完成帧数改变尺度。TT、AVB 固定预约服务和硬件/过渡仍由硬准入保护，奖励不能买通违规。

GB、实际 GCL 条目与 TT 额外等待在主实验作为指标，不再各加一项主奖励；GB 奖励只作为预先声明的消融。集中 Critic 辅助价值估计和更新，并不是知道每个 Agent 精确责任的因果裁判；统一团队回报本身也不保证 MAPPO 必胜或得到全局最优。

### 2. 第一层：TT Timing Projector

将在线安全协调层限制为“时间可行修正 + 完整验证”。包络先由下述不含包络的离线基模型计算，在线 $\mathcal F_{time}$ 只检查以下计划级条件：

1. $E_{i,e}^{env}\le x_{i,e}\le L_{i,e}^{env}$，未受控出口固定当前认证计划；源周期、释放相位、固定帧长、每周期一帧与路径不变。
2. 计划发送满足源释放 $r_J\le s_{J,e_1}$。
3. 基线循环实例顺序不变：相邻 $J\prec_e J'$ 有 $s_{J,e}+\tau_i\le s_{J',e}$，覆盖相邻超周期。
4. 计划跨跳因果 $s_{J,e_{h+1}}\ge s_{J,e_h}+\tau_i+d_h^{prop}+d_{h+1}^{proc}$。
5. 计划目的完成时刻满足 $c_J^{dest}-r_J\le T_i$，含最后链路传播。
6. 时间坐标参数在 80 ns 栅格，基线真实连续发送起点仍按物理帧长处理。

#### 2.1 先建立联合计划域，再计算每维 envelope

固定合法基线 $s^0,x^0$、源相位、循环实例身份/顺序、未受控端口计划、物理时延和时间坐标栅格。先用上列第 2–6 项建立**不含 envelope 端点**的 $\mathcal F_{plan}^{offline}$，源释放/目的期限和固定坐标锚确定有限坐标范围；禁止用 $[E^{env},L^{env}]$ 反过来界定这个基模型。

基模型按固定参考锚 $\zeta_{J,e}=s^0_{J,e}-x^0_{i,e}$ 和 $s_{J,e}^{plan}(\mathbf x)=\zeta_{J,e}+x_{i,e}$ 在展开时间轴生成约束，覆盖所有跨超周期邻接及跨跳实例；时间坐标在 80 ns 栅格，物理发送时长不取整冒充栅格时长。先检查 $x^0\in\mathcal F_{plan}^{offline}$ 且非空。对每个受控坐标离线分别解

$$
E_{i,e}^{env}=\min_{\mathbf x\in\mathcal F_{plan}^{offline}}x_{i,e},
\qquad L_{i,e}^{env}=\max_{\mathbf x\in\mathcal F_{plan}^{offline}}x_{i,e}.
$$

主端点以求解证书和逐维状态保存。若离线也未求得精确极值，只可用已证明的最小值下界/最大值上界向外对齐栅格形成外包络，并明确标记宽松性；不能将最小化/最大化的可行 incumbent 当成必要外端点。若主动缩域，必须另列为动作权限限制，所有方法一致。

令 $\mathcal B_{env}=\prod_{i,e}[E_{i,e}^{env},L_{i,e}^{env}]$，则

$$
\mathcal F_{time}=\mathcal F_{plan}^{offline}\cap\mathcal B_{env}
\subseteq\mathcal B_{env}.
$$

不强求严格包含；存在跨维耦合时通常不能由各维区间独立选点。包络只限定 Actor 的 proposal range，$\Gamma_{time}$ 判断联合计划可行性，Compiler/Validator 判断实际可安装性。$E<L$ 只表示该坐标存在非退化辅助边界，不保证逐维独立取值或整表通过完整验证；$E=L$ 的采样掩码为零，物理目标仍为 $E=L$ 而非零时间。包络不使用 ST 预测或测试性能生成，并绑定合同/基线/栅格版本，重配硬合同时重新计算。

#### 2.2 在线有时限修正与离线精确参考

正式在线接口是

$$
(\tilde{\mathbf x},\mathrm{status}^{time})
=\Gamma_{time}(\mathbf x^{pre};\mathbf x^{cur},\mathcal C_{time},B_{time}).
$$

$\mathcal C_{time}$ 包含上述联合约束及固定包络，$B_{time}$ 是完整 4 ms 控制链中给该阶段的子预算。算法、迭代上限、平局规则与超时处理预先冻结，候选序列不依赖 ST 性能。算法选择在同输入下确定；实际计算争用导致的 wall-clock 超时归入 $\xi^{ctrl}$ 并记录，给定相同控制实现轨迹才要求完整状态返回一致，不能把运行耗时假定成常数。超时取消与陈旧结果屏蔽须由控制执行机制保证；未完成或迟到的求解结果不得进入后续安装链。它以

$$
D_w(\mathbf x,\mathbf x^{pre})=\sum_{i,e}w_{i,e}(x_{i,e}-x^{pre}_{i,e})^2
$$

较小为设计目标，**主实现只要求有界时间与经过联合复核的可行输出，不承诺精确最小值**。可使用栅格求解或固定的连续求解→量化→有界 repair；后者必须在量化后重新核完所有时间条件，禁止各口独立 round 后直接部署。返回 PASS 才输出 $\tilde x\in\mathcal F_{time}$；不可行、无可行证据或耗尽预算都返回相应失败状态，交由整事务保持当前表。第二层失败后不继续搜索 ST 性能候选。

这里的联合投影目标是已经用于传播的 $\mathbf x^{pre}$，使合同修正尽量保留预候选；权重固定且不含 ST 性能。原始 $\hat x$ 到 $x^{pre}$ 的局部干预另记，不能在审计中丢掉。离线对相同预候选/约束/栅格可求理想参考

$$
D_w^\star=\min_{\mathbf x\in\mathcal F_{time}}D_w(\mathbf x,\mathbf x^{pre}).
$$

只有获得最优性证书才报告 $D_w(\tilde x,x^{pre})-D_w^\star$ 为最优性差距；仅有求解下界时报告下界与相应间隙上界，未有界时只报偏差/可行率/耗时。离线参考不计入在线预算，也不进入 Actor 或安全层性能输入。$\tilde x$ 仍不证明真实 FIFO、GB/GCL、AVB 预约或切换安全；完整准入保留在下一层。

### 3. 第二层：Compiler + Validator / C1

$$
\tilde G=\{\mathrm{Compiler}_e(\tilde{\mathbf x}_e)\}_e,\qquad
V(G^{cur},\tilde G,\mathcal C_{fixed},\mathcal S_{safe})=\mathrm{PASS}.
$$

Compiler 按固定规则形成发送子窗口、TT 保护区、GB 与 Flex，并合并相邻相同门状态。保护区合并不默认 Q6 全程开放，所有必要关闭/再开放状态计入实际条目。编译不得独立重选 TT 目标布局，不使用 ST 预测选择另一张表。

Validator 必须检查：

- **真实执行。** 按 arrival→Q6 FIFO→gate state→actual TX 的离散事件链，从源释放模拟全部跳与边界状态，核对实际 TT trace 实现计划；计划顺序不等式不能代替真实入队顺序。第 5 部分给出 E0 准入协议。
- **TT 与硬件。** 在实际 trace 上重查固定实例顺序、真实跨跳因果、$D_i=T_i$、整帧、GB 和非抢占残帧，核门控边界的 80 ns 与单口实际条目数 $\le B_{GCL}$（主设 256）。
- **AVB 固定预约。** 源 $R_j,B_j,L_j^{max}$、路径/队列、CBS 配置和信用规则不变；核固定 ST 包络与允许信用/过渡下的净预约服务证书。AVB 的 2 ms 仅是软指标，不作拒绝条件。
- **过渡与提交边界。** 验证旧表→新表拼接，覆盖在途 TT、队列积压、正在发送的帧、CBS 信用连续性和同步/版本偏差。未知到达用合同边界覆盖，不以单次样本代替全状态证明。

最终安装集合为

$$
\mathcal F_{install}(G^{cur})=\{\mathbf x\in\mathcal F_{time}:\mathrm{Compiler}(\mathbf x)\text{ 成功且 }V(G^{cur},\mathrm{Compiler}(\mathbf x),\mathcal C_{fixed},\mathcal S_{safe})=\mathrm{PASS}\}.
$$

实现先由 $\Gamma_{time}$ 返回经复核的 $\mathcal F_{time}$ 可行候选，再测试是否属于 $\mathcal F_{install}$；不宣称直接求解后者的精确最近点。编译、Validator 或控制时限任一失败，本轮整事务保持当前表，记录原因。主算法每轮只有一次最终联合时间修正与一套完整候选验证；传播前的局部预检查不代替本次核验，也不触发 ST 性能候选重试。即使通过验证，也须再经过 C2/C3 完整一致提交才能激活。

### 4. 主审计：Safety shield 如何改变提案（Safety intervention audit）

本节是 E2 正文主结果，与 ST E2E、TT/AVB 合同和控制耗时并列，不只作为 debug 指标。所有方法按相同日志口径报告合同干预。令 $\mathcal D$ 为非退化采样维度，$\ell=\lVert\mathbf L^{env}_{\mathcal D}-\mathbf E^{env}_{\mathcal D}\rVert_2$；填充与退化维度不计。成功激活事务内，比较该轮记录的原始连续提案与实际执行：

$$
d_{proj,k}=\frac{\lVert\mathbf x^{exec}_{k,\mathcal D}-\hat{\mathbf x}_{k,\mathcal D}\rVert_2}{\ell+\epsilon_t},
\qquad r_{unchanged}=P\!\left(\max_{j\in\mathcal D}|x^{exec}_{k,j}-\hat x_{k,j}|\le\varepsilon_{ret}\mid\mathrm{activated}\right).
$$

$\epsilon_t>0$ 为固定时间尺度；保留容差 $\varepsilon_{ret}$ 在测试前冻结，主设不超过半个 80 ns 栅格。另报严格相等比例、绝对修正量（μs）及 P50/P95/P99，使连续提案的必要栅格量化与更大合同修正可区分；诊断用量化不等于允许各口独立 round 后部署。无非退化采样维度时记 N/A。

以同轮 $x^{cur}$ 定义物理时间变化 $d^{req}=\hat x-x^{cur}$ 与 $d^{exec}=x^{exec}-x^{cur}$；它们是 $\delta$ 经 Decoder 后的时间量，与无量纲动作分开报告。另将本口预检查距离 $\|x^{pre}-\hat x\|$、最终联合修正距离 $\|x^{exec}-x^{pre}\|$ 与总偏差分别统计，防止漏掉传播前的合同干预。方向统计仅对 $|d^{req}|>\varepsilon_{dir}$ 的请求计算：两者均超过固定方向容差且符号相反才计 sign-flip；执行变化归零另计。另报原本请求保持某坐标、却因联合安全修正而改变的比例。维度保留率和整提案保留率同时报告，并单列请求改变布局的子集，防止大量无变化提案抬高结果。

$r_{reject}$ 的分母是全部提出的事务，按时间不可行、编译、FIFO/条目/预约/过渡核验失败列首个原因；控制/提交超时另计。$r_{fallback}$ 的分母为全部决策轮，分子为失败/超时导致整事务保持当前表的轮数；合法保持参考或成功提交相同表不算失败回退，另报无变化比例。成功条件下的 $d_{proj}$ 不混入回退旧表的距离；被拒提案、超时和未激活候选不能从总体记录删除。

这些指标量化性能偏好受到的合同干预；高修改率本身不能证明安全层在优化 ST，低修改率也不能单独证明 Actor 有效。还须核验安全层输入/目标白名单，并用相同安全层下的静态、规则、先验与学习对照判断收益。

### 5. 主审计：局部性与固定路径通信

**Predictor 本地性。** 固定本口事件、模型、mask、归一化和本地隐藏状态，只替换其他口缓存/消息；$p^{loc}_e,z^{pred}_e$ 应在预登记容差内不变。S0/P1 与 P2 单独覆盖，禁止同机跨口 attention 或隐藏状态拼接。

**Actor 消息边界。** 固定完整 $o^{actor}_e$（含允许的已接收消息）、模型和采样种子，只替换未声明的其他口数据，分布参数及原始 $\delta_e$ 应不变。单独改变合法父边消息时，下游动作允许改变；这正是声明的性能通信。无父边的上游不受其他口预测干预。不能沿用旧版“任何其他口预测变化均不得影响下游”的测试要求。

**路由与故障。** 错组、非父边、错周期/候选/窗口、迟到消息均不能进入有效槽；缺失用固定 mask，与 $q=0$ 区分。报告干预次数、最大差异和失败样例。审计进程的混配缓存不作为真实性能轨迹。

**Safety 输入隔离。** 固定同一 TT 候选、合同、当前状态及耗时/故障实现，仅改变 $p^{loc},p^{prop}$ 或预测缓存，安全结果应不变；接口应拒绝非白名单字段。其他口 TT 候选变化导致最终执行变化属于合同协调，不能报成 Actor 泄漏。

部署移除 Critic/集中训练缓存/E2E 回报后，固定相同本地输入和已收到的白名单消息重复提案；模型/配置哈希和数值容差公开。以上是待实施的审计协议，不宣称已通过。

### 6. 主审计：候选传播与实际执行一致性

下游决策使用 $G^{pre}_u$ 生成的消息，最终实际运行可能为 $G^{exec}_u\ne G^{pre}_u$。仅在离线审计中，固定同轮预测、冻结服务状态、场景权重、Mapper 和消息物理段，用最终实际表重新回放，得到 $\mu^{prop,exec}$；本次重算不发给 Actor、不改变本轮表、不产生新一轮提案。

$$
D_{prop}=W_1(\mu^{prop,pre},\mu^{prop,exec}),\quad
\Delta t_{prop}=|\mathbb E[T^{Q,pre}]-\mathbb E[T^{Q,exec}]|,\quad
D_{sched}=\frac{\|\mathbf x_u^{exec}-\mathbf x_u^{pre}\|_2}{\ell_u+\epsilon_t}.
$$

时间 $W_1$ 只在同一时域、相同事件条件且有限未截尾分布下直接计算；无到达不能伪设为时间零或无穷后计算普通 $W_1$。窗口到达发生概率变化另报 $|q^{pre}-q^{exec}|$、窗口流入/流出质量；只对双方有定义的条件时间报 $W_1/\Delta t$ 并公开覆盖率。INTERVAL 模式另报界端点变化及可达 bin 集合变化，不把区间伪装成点分布计算该距离。任一侧无到达/右截尾者单列，不能删去以缩小偏差。

报告全表不变率 $r_{table-unchanged}=P(G^{exec}_u=G^{pre}_u)$、$D_{sched}$、$D_{prop}$ 分布、全部消息有效率、失效/提交失败/保持旧表比例。表相等按同一相对周期内规范化门状态/持续时间比较，排除版本号/事务时间戳，避免把单纯版本更新计为布局变化。成功激活轮和回退轮分别报告，回退轮使用实际旧表重算。候选版本关联须能追溯到真实激活日志。

该审计只隔离“预候选被安全链改变”的影响；Mapper 与真实下游到达之间的误差由 E1.5 另测。偏差小只能支持已测场景下一次前向近似可用；偏差大则收窄传播收益结论并公开性能影响，禁止通过反向反馈、迭代重规划或给 Safety 增加 ST 目标掩盖。

## 强静态与学习控制对照

### StrongStatic 的硬可行准入与离线搜索

主工作点必须先找到至少一张满足 TT、真实 FIFO、GCL、AVB 预约及持续保持要求的合法静态表。研究的是合法静态参考的 ST 性能空间，不以“静态硬合同无解”制造动态需求；无合法静态基线的配置不进入主性能比较。是否 ST-suboptimal 由结果检验，不预先写成事实；“不存在一张对所有 ST realization 都最优的表”也不是已完成的证明。

StrongStatic 在与测试隔离的 calibration 轨迹上，按同一固定 $\lambda_D,\lambda_M,\lambda_A$、源帧账本和 AVB 口径优化 ST delay/miss 与 AVB 成本。静态无在线整表重构/修正，相关费用据实为零。搜索与动态/特权参考共用相同固定实例顺序、整表时间坐标域、路由、帧合同、GB、$B_{GCL}$、CBS、Compiler/Validator；静态表只需验证其安装和持续保持，动态方法还须验证每次切换，不人为向静态收取不存在的换表成本。

实现固定候选生成/搜索器、随机种子、多初始化数 $N_{init}$ 和预算 $B_{static}$（同时报告候选数与 CPU/wall time），记录初始合法解、各次最优值、可行/拒绝率和 best-so-far 随预算曲线。可用同一搜索器并给静态至少相等的单次离线优化预算；若求解器/预算不同则完整披露并做预算饱和检查。ASAP 或人工表只作初始化，不能直接命名为 StrongStatic。超参数和最终表由 calibration/validation 选择，测试期间一张表固定执行，不读取测试未来或按测试结果重新选择。

主工作点和负载档在 calibration/E0 冻结，公开搜索尝试及未准入原因，不剔除最终测试中动态无收益的预定档位。calibration 上的 StrongStatic/特权参考差距用于决定是否扩大研究，不代替独立测试效应。

### 有限预算特权参考

FixedOrderJointScheduleOracle 明确指 **fixed-order whole-table privileged search reference**：同动作权限下使用未来外生实现的有限预算搜索，不默认 exact，也不称严格性能上界。记录其候选生成、预算/多起点、最优值和可获得的界；只有经证明的最优值或有效界可作为数学性能界。未来信息只在隔离搜索/评分器中使用，不送往在线安全层或在线模型。九类主对照中仅该参考有此额外权限；单出口 PerfectLocalInfo 仍单列。

每个特权候选都从相同外生源实现重新回放，重算下游到达/积压；不得改流、源释放、路径、整表目标坐标权限或放宽条目/预约合同。有限预算失败不能证明物理无解，其与学习方法的差距也不能全归因预测误差。

静态参考前沿的代价可取 GB、条目或 TT 额外等待，不宣称搜索未证明的全体最优。两者均允许编译后保护区/Flex 数变化。主比较固定同一五项回报及合同；另在验证阶段预定有限的 $\lambda_A$ 档和 AVB 代价容差，冻结每个策略/表后报告 iso-AVB 参考前沿。匹配时同时报告 AVB backlog、2 ms 软目标超标与 P95/P99，无法匹配就公开 ST/AVB 权衡，不能靠删除种子、改变 reservation/CBS 或看完测试再调权重制造等代价。最长关门区间只作诊断，单独不增不能证明 AVB 无损或 ST 收益只来自开口位置。

| 主对照 / 消融 | 在线信息与执行 | 检验对象 |
|---|---|---|
| StrongStatic | calibration 搜索一次合法整表，test 固定 | 静态参考 |
| Prior+Prop+Rule | 固定本地训练先验→同一 Mapper/消息；同资源/规则 | 规则的实时预测消融 |
| Local+Prop+Rule | 本地预测+同一 Mapper/消息；同资源/规则 | 显式预测对规则的收益 |
| Prior+Prop+MAPPO | 先验+同一 DAG/Mapper；无包历史派生表示 | 学习控制的实时预测消融 |
| OwnerProp+MAPPO | 每组仅首个受控口预测，沿路径传播；下游不使用本地预测 | 旧 Owner 架构基线 |
| LocalOnly+MAPPO | 四口本地预测，无性能传播；四个 Actor 可并行 | 原局部独立架构基线 |
| Local+Prop+IPPO | 主方法同 Actor、消息、回报和预算；本地价值输入 | 集中价值信息消融 |
| **Local+Prop+MAPPO** | **各口本地预测 + 动作条件消息 + DAG Actors + 集中训练 Critic** | **主方法** |
| FixedOrderJointScheduleOracle | 未来外生实现的有限预算搜索；相同整表/合同权限 | 受限特权参考 |

共九类。OwnerProp 是明确的预测所有权消融，主方法无排他 Owner；LocalOnly 是无前向消息的并行对照，主方法各层 Actor 先后执行。不能只比较 OwnerProp 和 LocalOnly 就把差异归因于某一个因素；关键增量分别为 Local+Prop 相对 LocalOnly（在本地预测基础上增加传播）以及 Local+Prop 相对 OwnerProp（在传播基础上增加下游本地证据）。

**所有方法共同条件。** 相同固定路由、外生源、TT 长度/周期/实例顺序、当前表参考的 $\delta$ Decoder、局部预检查、最终 Safety、GB/GCL、AVB/CBS 与五项回报。各方法根据实际依赖计整链耗时与回退；Owner/LocalOnly 较少的计算/通信不虚增，主方法额外开销如实计入。另可做各组均采用同一层间等待的受控时延比较，但不得代替真实成本主结果。

**预测信息隔离。** Prior 组不读实时 $q,\pi,z^{pred}$、事件编码、包历史缓存；本地先验替换 $p^{loc}$，嵌入槽填固定零并使用固定 mask。Prop 输入也只来自相同先验与合法本地资源，不能通过 Mapper 或 Critic 偷带实时预测。下游仍可获得“先验经上游本轮动作映射”的消息，因此 Prior 对照控制的是实时包历史信息。所有使用本地预测的对照采用同一冻结 $\psi$。OwnerProp 屏蔽下游全部本地预测及其嵌入，保留相同下游资源。

主方法与 Prior 的差值包含概率头与本地嵌入两者的增量；如需单独归因 $q,\pi$，另加两边均无嵌入的同信息消融。Rule 也不得把 local/prop 需求相加或按独立证据相乘；首版有有效 PROB 消息时使用其动作条件到达分布评分，INTERVAL 消息时按固定保守区间评分，缺失时用 local，规则固定且不另训融合器。多组竞争使用相同预定场景回放，不读取未来真值。

**IPPO/MAPPO 单因素对照。** 两组的 Actor 输入、共享方式、初始化分布、Mapper/消息故障模型、团队 E2E 回报、PPO 配置、训练与计算预算、种子完全相同。价值基线统一在本轮上游动作之前取值：IPPO 为 $V_\phi(o^{base}_{e,k})$，MAPPO 为 $V_\phi(c_k^{train})$；双方均不将依赖上游本轮动作的消息回填到该冻结点基线。只调整价值可见范围，骨干规模和共享方式对齐；IPPO 不改成 local reward。

以较低越好指标 $M$ 定义

$$
\begin{aligned}
\Delta_{pred}&=M(\mathrm{Prior+Prop+MAPPO})-M(\mathrm{Local+Prop+MAPPO}),\\
\Delta_{prop}&=M(\mathrm{LocalOnly+MAPPO})-M(\mathrm{Local+Prop+MAPPO}),\\
\Delta_{local}&=M(\mathrm{OwnerProp+MAPPO})-M(\mathrm{Local+Prop+MAPPO}),\\
\Delta_{critic}&=M(\mathrm{Local+Prop+IPPO})-M(\mathrm{Local+Prop+MAPPO}).
\end{aligned}
$$

效应、独立任务轨迹置信区间及实际控制成本同时报告，不预设上述差值为正。$\Delta_{prop}$ 包含通信带来的因果输入和实际延迟影响；$\Delta_{critic}$ 仅检验集中价值信息。与有限预算 Oracle 的差值混合信息、策略类、训练与搜索误差，不能称纯预测损失。

PerfectLocalInfo 仍是固定其他口的单出口特权诊断，单列且不替换九类比较。统一团队回报相对纯本地回报的效应没有被本组实验单独识别，因此不扩大这方面的贡献表述。

# 第五部分 本出口策略、TT 时间动作、本地编译与影子表

## PPO / MAPPO：基于本地 ST 预测的 TT 整表时间布局重编排

### 1. 三个时间尺度与核心原则

| 对象 | 粒度 | 含义 |
|---|---|---|
| GCL 超周期 | 8 ms | 门控重复执行与一次控制更新周期 |
| ST 预测 | 16×0.5 ms | 冻结点后第 4–12 ms 的本地新到达，不等于冻结→冻结 RL step |
| TT 释放 | 0.5/1/2/4/8 ms | 固定源周期 $T_i$，每次一帧、长度按流固定 |
| TT 时间动作 | 每口一次整张表的目标向量 | 按流坐标展开所有周期实例，实例顺序固定 |
| GCL 编译 | 80 ns | 实际发送机会与保护区的硬件时间栅格 |
| 保护带 | 12.4 μs | 防止非抢占异步帧侵入 TT 发送 |
| Flex | TT 保护区与 GB 的补集 | 段数、长度、位置和总量由编译结果派生 |

例如 $(A,e_{01})$ 的 $I_5$ 条件概率为 0.45，只表示首帧在下一周期相对 2.0–2.5 ms 的条件到达概率。它不对应第 5 个 TT 动作，也不意味着每 0.5 ms 重新决策一次。不同出口即使预测同一组 ST，也各自使用本地 $(q,\pi)$。

### 2. 每周期控制闭环

1. $f_k=t_k+4$ ms 冻结全部本口历史/资源，四口 Predictor 并行。当前 $G_k$ 持续运行。
2. $A_{3u}\parallel A_{4u}$ 各输出一次整表 $\delta_u$；Decoder 与已有工具的局部预检查生成 $(\mathbf x^{pre}_u,G^{pre}_u)$，失败则按规定采用当前认证表作预候选。
3. 每个上游 Mapper 对本口多组 Q7 联合回放，沿固定边发送候选版本绑定的下游到达消息。消息接收截止后不再更改本轮 Actor 输入。
4. $A_{01}\parallel A_{02}$ 用自己的本地预测、有效父边消息和缺失 mask 各输出一次整表 $\delta_d$，再做同类 Decoder/预检查。
5. 全部 $\mathbf x^{pre}$ 汇入联合 $\Gamma_{time}$，只按硬时间合同修正；最终 Compiler/Validator 核真实 FIFO、TT、GB/GCL、AVB 预约与过渡。
6. C1 全部通过后，在 $t_c$ 前完成 C2/C3，等待第 8 ms 统一激活。任一步失败/超时则整事务保持当前表。最终表变化仅进入离线传播一致性审计，不让下游重规划。

### 3. 当前表参考的 $\delta$ 整表动作

#### 3.1 一次完整向量

$$
a_{e,k}=\boldsymbol\delta_{e,k}=[\delta_{i,e,k}]_{i\in\mathcal T_e}\in[-1,1]^{N_e},
\qquad N_e=|\mathcal T_e|.
$$

坐标按固定 FlowID 排列，所有坐标联合构成一份动作；按流参数化、整表联合决策、逐帧验证、整表原子安装。$N_e$ 由全局流表派生，与 16 个预测 bin 无关；不增加逐实例动作、permutation 或逐流提交。

#### 3.2 Decoder：零动作是 KEEP 提案

令 $c_{i,e,k}=x^{cur}_{i,e,k}$ 为本轮冻结时的当前认证坐标，$[E^{env}_{i,e},L^{env}_{i,e}]$ 为固定合同包络。定义

$$
\hat x_{i,e,k}=D_i(\delta_{i,e,k};c_{i,e,k})=
\begin{cases}
c_{i,e,k}+\delta_{i,e,k}(c_{i,e,k}-E^{env}_{i,e}),&\delta_{i,e,k}<0,\\
c_{i,e,k},&\delta_{i,e,k}=0,\\
c_{i,e,k}+\delta_{i,e,k}(L^{env}_{i,e}-c_{i,e,k}),&\delta_{i,e,k}>0.
\end{cases}
$$

$\delta=-1$、$+1$ 分别到包络端点；$\delta=0$ 生成当前表目标，$\boldsymbol\delta_e=\mathbf0\Rightarrow\hat{\mathbf x}_e=\mathbf x_e^{cur}$。这只是本口 KEEP **提案**，不能强制联合安全层也保持该口。KEEP 提案、成功提交相同表、局部预检查失败、整事务失败保持分别统计。

当 $E=L$，坐标固定为该值并从随机采样/log-prob 排除。$x^{cur}=E$ 或 $L$ 时某一侧余量为零，该侧多个 $\delta$ 可以解码到同一目标；这不导致 $\delta$ 动作密度失效，不能除以 Decoder 的零 Jacobian。主版保留该连续动作参数化，报告解码无效/塌缩比例，不另增离散 KEEP 头。Padding 不代表物理时间。

#### 3.3 固定 pattern 与三阶段时间坐标

$$
\boldsymbol\delta_e\xrightarrow{D}\hat{\mathbf x}_e
\xrightarrow{\text{局部预检查}}\mathbf x_e^{pre}
\xrightarrow{\Gamma_{time}}\tilde{\mathbf x}_e
\xrightarrow{\text{硬核验/提交}}\mathbf x_e^{exec},\qquad
s_{J,e}^{plan}=\zeta_{J,e}+x_{i,e}.
$$

$\zeta_{J,e}=s^0_{J,e}-x^0_{i,e}$ 仍绑定基线/实例身份，用于展开所有同流周期实例；Decoder 参考的 $x^{cur}$ 每轮更新，固定锚 $\zeta$ 不更新。两者无冲突。预检查表用于 Mapper，最终表用于实际执行；原始动作始终是 $\delta$。Validator 保留已执行前缀，不用新布局回写过去。TT 保护区、GB 和 Flex 结构由 Compiler 派生。

### 4. Actor 观测与 Local Compiler

$$
\begin{aligned}
o^{base}_{e,k}&=[z^{pred}_{e,k},\{p^{loc}_{g,e,k}\}_{g\in\mathcal G_e},
G_e^{cur},\mathrm{TT}^{local}_e,\mathrm{Flex}^{cur}_e,\mathbf Q^{local}_e,\mathrm{CBS}_e],\\
o^{actor}_{e,k}&=[o^{base}_{e,k},\{p^{prop}_{g,u\to e,k},bounds,mode,valid,coverage\}_{(g,u,e)\in\mathcal A_{msg}}].
\end{aligned}
$$

上游无父边，消息槽固定为空/缺失；下游按固定组/父边槽并列输入 local 与 prop。消息有效性不能由未来真实发生标签决定。本地 TT 特征含当前坐标/包络、周期/固定帧长、实例顺序；Flex 为本口区间/分格摘要；队列和 CBS 均为冻结本口已观测状态。$z^{pred}$ 只在本口使用。

其他出口原始预测、历史/嵌入/隐状态、整口队列、完整 GCL、新动作向量、集中 Critic 或未来真值均不直接进入本口 Actor。允许的跨口入口仅为固定父边的到达消息。同机两出口也不得用共享 attention 绕过该边界。

局部预览和最终 Local Compiler 复用同一确定性 TT/GB/Flex 编译规则，最终输入为 $\tilde{\mathbf x}_e$ 与本口硬合同。编译不自行优化 ST 或重选布局；预览成功仍须完整 Validator/C1。Q6 保留真实 FIFO 子窗口，Q7/Q4/Q0 在 Flex 服务。AVB 超过 2 ms 软目标只进回报/指标。

#### CTDE：端到端团队训练的可执行协议

##### 1. 主方法与 Critic 输入

主方法是 **Local+Prop + DAG-Structured MAPPO / E2E-TeamReward**。离线训练允许在仿真器中用当前策略反复生成新轨迹；这属于部署前的 on-policy 仿真训练，不是对一份固定网络日志任意复用动作结果。预测器 $\psi$ 先完成 E1 与合法改表数据校准，再冻结；PPO 更新 Actor $\theta$ 和 Critic $\phi$，不在批内改预测器而使观测含义漂移。所有预测型对照使用同一冻结 $\psi$、预处理、归一化统计与嵌入权重；动态事件缓冲仍随真实本地事件更新。Actor/Critic 接收预测特征时停止向 $\psi$ 反传，不能通过共享骨干、BatchNorm 更新或优化器参数重叠间接修改预测器；$\theta$ 与 $\phi$ 也互不共享可训练参数。

合作 PPO 的集中价值网络/本地策略分工参考 [MAPPO 原始论文](https://arxiv.org/abs/2103.01955)，其经验成功不构成本 TSN 系统的性能或最优性证明。本文显式区分真实环境状态 $s_k$、本地观测 $o_{e,k}$ 与训练摘要：

$$
c_k^{train}=B_{train}(s_k),\qquad V_\phi(c_k^{train}).
$$

$c_k^{train}$ 在采样本轮上游动作**之前**冻结，可含各口合法 $o^{base}_e$、静态路径关联、当前已提交/待激活版本、当前队列/信用、已释放在途 ST 的源年龄与当前时钟相位。它是训练用摘要，不保证充分 Markov；不能把 $[\{o_e\},P]$ 直接等同于完整 $s_k$。主 Critic 不输入隐藏任务真值 $Z_g$、未来释放/到达、未来随机种子、Oracle 解或本轮执行后的状态。上述未来结果只用于随后回报/监督目标。

Prior+Prop+MAPPO 的 Critic 同样删除实时预测嵌入、预测输出和 packet-history 派生缓存，只保留其允许的先验、资源与训练状态摘要。若用固定 episode 剩余步数辅助有限期价值估计，IPPO/MAPPO 两组一致提供这一预定训练属性；它不是未来事件标签，也不进入在线 Actor。IPPO 的价值输入只取本口冻结的 $o^{base}_{e,k}$，MAPPO 使用同一冻结点集中摘要；两者均不将依赖本轮上游动作的消息回填进该时点价值基线，始终使用相同团队回报。

##### 2. 固定源帧 cohort 与跨周期账本

预热后的首个冻结点为 $f_0$，源释放测量窗口固定为 $[f_0,f_{K_{meas}})$，计费区间为 $[f_0,f_{K_{ep}})$，其中 $K_{ep}>K_{meas}$。窗口内释放的唯一源帧构成 $\mathcal J_{ep}$，不按目的端完成窗口选择样本，也不漏计首个冻结点前后的 4 ms。测量后保留固定尾段，普通背景与既定外生生成过程继续，不能清空在途帧、CBS 信用或历史缓冲。episode/测量阶段标签不提供给 Actor。

$K_{ep}$、尾段长度和失败清算规则在 E0/验证集冻结，覆盖预期 ST 完成跨度，并使 $f_{K_{ep}}>\max_{J\in\mathcal J_{ep}}(r_J^{src}+D_{g(J)})$；可按测量终点加最大固定期限和至少一个结算步预留。终止前先处理同刻完成/到期事件，再结算终端费用并置 done，防止边界 miss 漏计。若尾段仍有未完成/丢失帧，它们保持 miss 身份和审计记录，按事先固定的终端失败费用并入 ST 成本，不能以提前 reset 删除；这类结果不再声称具有未截断真实完成时延。正式 E2E 时延继续排空能完成的帧并对未完成者说明删失，分母不删帧。

训练账本每帧记录：$r_J^{src}$、$D_{g(J)}$、是否 cohort、各口 ready/TX/完成及 GCL 版本、目的完成 $c_J^{dest}$、是否已计 miss。记录可集中在离线仿真器，既不传给 Actor，也不由安全层用来选择 ST 性能方案。同一帧经过两口不生成两份 E2E 成本；一帧跨三步也不能每步重新从源计时。

##### 3. 五项主回报：按时间累计 E2E，而非只在完成时发负奖励

仅在完成时扣整段负时延，配合折扣/截断可能奖励“把坏结果拖到以后”。主设置采用未折扣有限 episode（$\gamma=1$）和逐步在途时间费用；训练目标是按固定 $D_g$ 归一的时延总成本与 miss 代价，尾部分位改善另由测试检验。设 $B_k=[f_k,f_{k+1})$，$N_{ref}>0$ 为训练前固定的归一化常数：

$$
C_{ST-delay,k}=\frac1{N_{ref}}\sum_{J\in\mathcal J_{ep}}
\frac{|[r_J^{src},c_J^{dest})\cap B_k|}{D_{g(J)}}
+\mathbf1\{k=K_{ep}-1\}\frac1{N_{ref}}\sum_{J\in\mathcal U_{ep}}\kappa_{fail,g(J)},
$$

$$
C_{ST-miss,k}=\frac1{N_{ref}}\sum_{J\in\mathcal J_{ep}}
\mathbf1\{r_J^{src}+D_{g(J)}\in B_k,\ c_J^{dest}>r_J^{src}+D_{g(J)}\}.
$$

$\mathcal U_{ep}$ 是终点仍未完成/已丢失的 cohort 帧，$\kappa_{fail,g}>0$ 是训练前冻结的无量纲失败费用，只在最后一步计一次。未完成/丢失帧在区间记法中取 $c_J^{dest}=+\infty$，计费只积到固定终点；这不是伪造完成时延。实际实现只累计本步已经经过的在途时间，不读取未来 $c_J^{dest}$；区间写法用于事后核算。到期时只触发一次 miss，完成恰好等于截止期不算超时；同刻完成/到期事件按这一规则处理。丢失帧不能提前停止累计以规避代价，按固定终端规则清算。

当整个 cohort 在终止前完成、$\mathcal U_{ep}=\varnothing$ 时，终端失败费用为零，有

$$
\sum_k C_{ST-delay,k}=\frac1{N_{ref}}\sum_{J\in\mathcal J_{ep}}\frac{d_J^{E2E}}{D_{g(J)}},\qquad
\sum_k C_{ST-miss,k}=\frac{N_{miss}}{N_{ref}}.
$$

未完成帧适用终端费用/删失协议，不能把这条完成帧恒等式冒充其真实延迟。主回报仍只有五项：

$$
R_k=-\lambda_D C_{ST-delay,k}-\lambda_M C_{ST-miss,k}
-\lambda_A C_{AVB,k}-\lambda_m C_{reconf,k}-\lambda_p C_{projection,k}.
$$

其余三项的主核算固定如下，内部系数和尺度同五个主权重一起在验证阶段冻结，不另开主奖励项：

| 项 | 固定核算接口 |
|---|---|
| $C_{AVB,k}$ | $\sum_e\int_{B_k}Q_{4,e}^{bit}(t)dt/A_e^{ref}$，$A_e^{ref}>0$ 的量纲为 bit·time；2 ms E2E 软目标超标率另报 |
| $C_{reconf,k}$ | 对 $B_k$ 内实际激活事件，累计 $\lVert x^{new}-x^{old}\rVert_2/(\ell+\epsilon_t)$ 加固定换表费用；未激活则为零 |
| $C_{projection,k}$ | 时间投影已返回时的 $\lVert \tilde x-\hat x\rVert_2/(\ell+\epsilon_t)$，加首因硬拒绝/控制超时的固定费用；无投影结果不虚构距离，但失败费用照计 |

$\ell=\lVert\mathbf L^{env}_{\mathcal D}-\mathbf E^{env}_{\mathcal D}\rVert_2$ 是标量时间尺度，与第四部分一致，不是逐维宽度向量；所有范数只取非退化采样维度。失败/超时标签避免同一首因重复收费。$C_{reconf}$ 对实际激活收费，$C_{projection}$ 对原始提案受到的处理反馈收费，两者不能用候选表冒充执行表。GB、条目与 TT 额外等待仍只作指标，硬条件不可被回报抵消。

同一 $R_k$ 提供给所有参与训练的出口，不按路由手工分摊、不给最后一跳独占奖励。每口等待分解只用于诊断；它不是精确的个体因果贡献。五项权重、参考尺度、终端费用和 episode 协议在测试前冻结，不能用每步已完成数、预测命中数或最终测试结果动态归一。

##### 4. 原始 $\delta$ 动作与 rollout 消息的 PPO 概率

令 $\mathcal D_e=\{j:j\text{ 为真实 TT 坐标且 }E^{env}_j<L^{env}_j\}$，排除退化/padding。各层 Actor 按拓扑顺序采样一份完整向量，$z_e\sim\mathcal N(\mu_\theta(o^{actor}_e),\mathrm{diag}\,\sigma_\theta^2(o^{actor}_e))$、$\delta_e=\tanh z_e$，再由确定性 Decoder 生成原始目标。对角采样仅是整表向量分布参数化，无逐流安装权限。

PPO 的动作是 $a_e=\boldsymbol\delta_e$，其密度仅需 tanh 变换：

$$
\log\pi_\theta(\boldsymbol\delta_e\mid o^{actor}_e)
=\sum_{j\in\mathcal D_e}[\log p_\theta(z_j\mid o^{actor}_e)-\log(1-\delta_j^2)].
$$

Decoder 的 $\partial\hat x/\partial\delta$ 不属于 $\delta$ 密度的 Jacobian；边界零余量、栅格量化、局部修正及最终多对一 Safety 都不能改变已采样动作。无非退化维时跳过该口概率/熵损失，环境与团队统计照常。不得将 $\delta$ clip 成端点后沿用旧密度；实现用稳定 tanh log-prob。

$$
\rho_{e,k}(\theta)=\exp\{\log\pi_\theta(\boldsymbol\delta_{e,k}\mid o^{actor,roll}_{e,k})
-\log\pi_{\theta_{old}}(\boldsymbol\delta_{e,k}\mid o^{actor,roll}_{e,k})\}.
$$

rollout 中先实际采样上游 $\delta_u$、构建其候选并生成消息，再采下游 $\delta_d$。Buffer 必须保存：本口 $o^{base}$、当时接收的完整消息/缺失状态、最终 $o^{actor,roll}$、$z,\delta$、$\hat x,x^{pre}$、old log-prob、$x^{cur}$、mask、候选/Mapper/预处理版本、最终执行/提交/耗时结果。**PPO 多个 epoch 使用这批固定消息，不重新采上游动作，不用新策略/最终执行表生成的消息替换它。**

给定保存的原始联合动作，消息是其当时条件链的一部分；new/old ratio 评估同一条链的条件因子。完整联合似然比为 $\rho_k^{joint}=\prod_e\rho_{e,k}$。主 MAPPO 仍采用逐 Actor clipped surrogate，是合作 PPO 的训练近似，不将它写成精确联合 clipping 或性能改进保证。

Service Mapper 与 Safety 均作 stop-gradient 的固定执行接口，不要求通过它们反向求导；上游影响由该联合条件策略的 score 与真实团队回报学习。被修正、拒绝、消息失效、提交超时的 transition 全部保留，安全结果不替换原始动作概率。

##### 5. 团队优势、PPO 更新与责任边界

设 $b_k=0$ 仅表示真正环境终止，其他情况为 1。用 [GAE 原始方法](https://arxiv.org/abs/1506.02438) 计算：

$$
\delta_k^V=R_k+\gamma b_kV_{\phi_{old}}(c_{k+1}^{train})-V_{\phi_{old}}(c_k^{train}),\qquad
\hat A_k=\delta_k^V+\gamma\lambda_{GAE}b_k\hat A_{k+1}.
$$

真正 episode 结束时 bootstrap 为零；只是 rollout/batch 截断时，从真实下一个摘要 bootstrap，不能清空队列/账本或当作 episode done。数值递推在 chunk 末尾截断优势尾项时明确这是有限长度近似，未来成本由 bootstrap 承接；先用未归一化 $\hat A_k$ 构造 $\hat V_k=\hat A_k+V_{\phi_{old}}(c_k^{train})$ 并固定；随后只对 Actor 的优势做标准化，不把标准化值回写 Critic target。old log-prob、old value、优势与 value target 全部 stop-gradient。$\lambda_{GAE}$ 与五个回报权重不同，按验证集选择，并报告 rollout 跨度、跨 chunk ST 比例及终端未完成率。

共享 Actor 使用各口原始动作比例和同一团队优势的 [PPO clipped surrogate](https://arxiv.org/abs/1707.06347)：

$$
L_{actor}=\mathbb E_{k,e}\!\left[\min\{\rho_{e,k}\hat A_k,
\mathrm{clip}(\rho_{e,k},1-\epsilon_{PPO},1+\epsilon_{PPO})\hat A_k\}\right],\qquad
L_{value}=\mathbb E_k\left[(V_\phi(c_k^{train})-\hat V_k)^2\right],
$$

其中 $\hat V_k$ 始终来自未归一化 GAE，Actor 式可用其固定标准化版本。IPPO 用相同 $R_k,b_k$，仅将价值输入换成该口冻结的 $o^{base}_{e,k}$（及一致的预定有限期属性），得到对应 $\hat A_{e,k}$；不把局部 Critic 等同于局部回报。Critic 和 Actor 参数分离；Actor 的前向只能取本地输入与固定父边消息，集中摘要只能影响训练目标/优势，不能经共享隐层成为 Actor 特征。优势归一、entropy、clip、epoch/minibatch 与训练预算对照一致，并记录 KL/clip fraction 等训练诊断。

DAG 条件策略的 score 在保存的动作/消息链上为 $\nabla_\theta\log\Pi_\theta=\sum_e\nabla_\theta\log\pi_\theta(\boldsymbol\delta_e\mid o^{actor,roll}_e)$，因此共享 E2E 结果能影响各口参数更新。这说明**为什么可以在局部观测下学习团队目标**，不意味着状态价值基线已经识别每口责任。集中 Critic 可以改善条件价值估计和更新方差，但不是反事实贡献分解；使用近似 Critic、有限 GAE 与 clipping 也不保证无偏或单调性能改善。主方法不额外叠加新的 credit-assignment 网络。

##### 6. 一批离线训练与部署清单

1. 固定预测器、当前 $\theta_{old}$、静态合同/预处理和同一安全执行器；从独立外生任务实例生成完整包级 rollout。相同种子指相同源端外生过程，不是把旧控制器的下游到达/观测强行复放给新策略。
2. 冻结时先构建各口 $o^{base}_e$ 与 $c^{train}$；按 DAG 先采上游 $\delta$，生成预候选与消息，再采下游 $\delta$。保存 rollout 消息和每口原始动作/log-prob，再运行最终安全链，记录真实耗时/提交结果。
3. 推进网络到下一冻结点，更新实际源帧账本、五项团队成本与下一摘要；保存所有拒绝/回退 transition，处理 rollout 截断与真正终止的不同 mask。
4. 以这批轨迹固定的 return/GAE 更新 Critic 与共享 Actor；禁止把计算时的新预测器、已修正动作或执行后摘要替换进 old-policy 样本。有限 PPO epoch 后丢弃旧策略批次，再收集新 rollout，不用混合任意版本的 replay buffer。
5. 测试前冻结 $\psi,\theta$、预处理、掩码、合同/安全层版本与确定性评估规则。在线部署本地采集/预测器/Actor、确定性 Service Mapper/固定路径消息、Decoder/局部预检查、Compiler/Validator 和安全提交，不部署 Critic、优化器、GAE、集中性能摘要或 E2E 回报通道。离线统计服务不可成为在线依赖。

#### 训练接口的实现验收

训练前用短合成时间轴核对以下接口；它们验证核算和数据流，不替代 E0 的包级网络实验或硬安全证明。

| 检查 | 应满足的结果 |
|---|---|
| 跨三步、两出口的同一源帧 | holding 时间和等于真实 E2E；各口账本不重复收费，miss 最多一次 |
| 完成恰好等于 deadline、终端仍未完成 | 前者不计 miss；后者累计到固定终点、miss 一次、失败费用一次，保留删失身份 |
| 冻结 4 ms→激活 8 ms→下次冻结 12 ms | 4–8 ms 属旧表，8–12 ms 才可能属新表；失败整事务保持旧表 |
| 多个整表提案被修成同一布局/被拒绝 | 各自原始 log-prob 保留；参数更新前同提案 old/new 比例为 1；不删除失败 transition |
| rollout 截断与真实终止 | 前者保留状态/账本并 bootstrap；后者先完整清算再置零；value target 不受优势标准化改变 |
| Actor 信息边界 | 固定本地输入和允许的已收消息，替换未声明的他口缓存时 $\delta$ 不变；改变合法父边消息允许下游动作改变 |
| PPO 消息一致性 | 固定 rollout 动作/消息，参数未更新前 old/new ratio 为 1；更新时不重采上游动作或重建消息 |
| 边界 Decoder | 当前坐标在包络端点时仍能记录有限 $\delta$ log-prob，不除以零 Jacobian；零向量解码为当前表 |
| 部署裁剪 | 移除 Critic、E2E 采集/回报、集中训练缓存后，同本地输入提案不变；导出物不含这些在线依赖 |

### 6. PPO / MAPPO 的定位

需要检验的是本地普通流预测能否在 E2E 团队训练与局部执行下改善 TT 时间决策；集中 Critic 的附加增量由同回报 IPPO/MAPPO 对照检验。本轮不另改 IPPO 回报，也不将未隔离的目标效应归为 MAPPO 优势。多组预测重叠、多峰分布、狭窄联合时间域及 AVB/条目边界可能使规则不足；这些是实验场景，不是预设 MAPPO 必胜的结论。

PPO 类 Actor 提出经 E2E 反馈训练的本地性能偏好，在线安全协调层负责跨跳与合同修正。若规则接近 Oracle 或 MAPPO 与 IPPO 无可重复差异，按实测降低学习器的贡献定位，不改变比较权限或让在线安全协调层优化 ST。

## 本地编译与影子表

$$
\boxed{\text{DAG 分层提案与单向传播}\rightarrow\text{TT 时间投影}\rightarrow\text{本地 GCL 编译}\rightarrow\text{Validator/C1 完整硬检查}\rightarrow\text{准备/提交}\rightarrow\text{定时激活}}.
$$

系统只保留当前操作表和本轮影子表；候选组合通过核验及一致提交后，仍等待 $t_k+8$ ms 边界统一激活。候选预览仅用于 Mapper，在软件中不装入数据面；最终影子表的编译、预装和 COMMIT 均不提前改变当前周期执行。下游接收固定父边消息，不能选择其他口整张 GCL 或多张性能方案。

### 1. 整体系统架构与组件部署

每受控出口一个逻辑 Agent；同机可共享进程/同类权重，本口事件、预测隐状态和队列缓存隔离。每口保留 PacketCollector、Set Transformer、ModernTCN、Predictor、Actor、Decoder 和 Compiler；上游增加确定性 Service Mapper/固定边消息发送，下游增加固定槽消息接收。局部预检查复用已有安全工具，不新增学习网络。

```text
数据感知层：四口各自 AVB/BE → Set Transformer + ModernTCN → p_loc
因果协调层：A3u ∥ A4u → δ/Decoder/预检查 → Service Mapper
                     ├─ m_A: e3u → e01 ─┐
                     ├─ m_B: e4u → e01 ─┤→ A01（保留 p_loc）
                     └─ m_C: e4u → e02 ───→ A02（保留 p_loc）
安全执行层：四口 x_pre → Γ_time → 最终 Compiler/Validator → C2/C3
                                                    ↓
                                      t_k+8 ms 整事务统一激活
```

两个白名单严格依第三部分消息协议：性能分布只发固定子边；Safety 只收 TT 候选/当前表、固定合同、安全摘要和事务元数据。消息网关检查周期/边/版本后，Actor 只读取分布/有效性，不能解析候选哈希恢复上游动作。安全队列/信用摘要只服务过渡认证，不转交 Actor。

### 2. 周期在线运行流程

| 阶段 | 性能链 | 安全/数据面边界 |
|---|---|---|
| 持续采样 | 各口只记录本口 AVB/BE | 当前认证表执行 |
| $f_k=t_k+4$ ms | 冻结历史/资源，四口 Local Predictor 并行 | 不换表，不读取之后事件 |
| 第 1 层 | $A_{3u}\parallel A_{4u}$ 输出整表 $\delta$，Decoder/本口预检查 | 预候选无激活权 |
| 前向映射 | Q7 联合服务回放，沿三条固定边各发一次消息 | 无性能反向边/重规划 |
| 第 2 层 | 接收截止后 $A_{01}\parallel A_{02}$ 各执行一次，缺失消息带 mask | 不重跑 Predictor/Actor |
| 联合安全 | 汇集 $\mathbf x^{pre}$，$\Gamma_{time}$ 只修合同 | 不读 local/prop 预测 |
| 编译/核验 | 最终 Compiler + Validator / C1 | 真 FIFO、TT、GB/GCL、AVB 预约、过渡 |
| 预装/提交 | PREPARED/C2、COMMIT/C3，完整依据在 $t_c$ 前取得 | 事务应答不得夹带性能信息 |
| 第 8 ms | 按统一 baseTime 激活最终表，否则一致保持旧表 | 最终版本和执行结果只记录/离线审计 |

主实验四口属于同一事务，未受控口为固定合同边界。不能只回退下游而保留同事务上游新表。各参与者的预装、撤销、迟到结果屏蔽及混合版本处理沿用既有认证要求；真正独立且经认证隔离的事务才可分别提交。

### 3. Compiler + Validator 的执行验证与过渡检查

离线准备合法基线、固定坐标归一化边界、循环帧实例序列、ST 单事件准入依据、AVB 预约服务边界及可达过渡状态。Timing Projector 只管计划时间关系；C1 必须基于编译表与真实执行结果判断完整准入，不能复用“投影已通过”代替验证。

#### 3.1 E0 必须实现的真实 Q6 FIFO Validator

验证器输入固定源释放与长度/路径、旧/候选 GCL、实际或认证覆盖的初始队列/信用、传播/处理时延、非抢占规则、同刻入队 tie-break 与计划 TT trace。核心执行为

$$
\text{源释放}\rightarrow\text{逐跳实际 RX/ready}\rightarrow Q6\ \mathrm{FIFO}\rightarrow\text{gate eligibility}\rightarrow\text{actual TX}.
$$

下游 ready 由上游**实际**发送完成、传播和处理推得。仿真器不能在执行时查计划表按 FlowID 挑帧，也不能把计划起点直接写成 actual TX 来制造一致。相同时刻先处理所有到期到达/完成/门状态事件，再按冻结的确定性 tie-break 做选择，避免实现顺序暗改 FIFO。

Q6 只能发送队头。门开时仍检查整帧可发送、链路是否占用；Q7/Q4/Q0 与管理流按相同非抢占执行规则推进，CBS 信用持续演化。若计划 A 在 B 前，但 B 先入队，不能绕过 B 发 A；实际 trace 若不同于计划直接拒绝。

$$
\mathcal T^{actual}_{TT}=\mathcal T^{plan}_{TT}(G^{cur}\rightarrow\tilde G,\ t_{activate},\ \mathcal S_{safe}),\qquad
\mathcal T_{TT}=\{(J,e,t_{start},t_{finish})\}.
$$

比较对象是以激活时刻拼接的旧表→候选表计划，保留激活前已经执行的前缀，不能按新布局回溯改写。某在途帧的上游可经历旧表、下游经历新表，必须沿同一帧身份核其拼接因果。按帧 ID、出口、起止时刻逐条比较，不能只比帧数或顺序。主仿真采用整数时间单位和真实线上长度，不把每帧持续时间向 80 ns 取整后冒充物理发送；硬件测量容差另行预先定义，并计入安全裕量，不据此放宽跨跳因果与期限。对相同释放/初态，实际 trace 必须实现计划；对认证允许的不同初态及扰动，也须满足相应鲁棒计划与合同，不能把单一初态一致称为全状态证明。

实际 trace 上再次核源释放、固定循环顺序、每跳因果、TT 目的完成期限及跨周期帧身份。覆盖 S3/S4 汇聚到 S0、不同流同刻释放、Q6 队头错序、Q6 窗口过度合并、边界在途 TT 等慢例/反例。E0 只有在反例被拒绝、合法基线被正确执行后才进入 Oracle 性能比较。此处规定的是必须实现的代码准入标准，本轮未声称已运行该网络验证器。

#### 3.2 GCL 256 条的实际计数与统计

GCL 按最终门向量与持续时间序列计数，合并相邻完全相同门状态后再核 $N_{entry,e}\le B_{GCL}$（主设 256）；Q6 内部关闭/再开放、保护带及管理机会形成的状态均计入。保护区合并不能隐藏子窗口。循环首尾按同一设备格式处理，不为减条目改变共同基时间或真实门序列。

E0 在训练前逐口报告：

| 量 | 口径 |
|---|---|
| $N_{entry,e}^{baseline}$ | 合法基线的实际条目数 |
| $N_{entry,e}^{Oracle}$ | Oracle 最终所选**通过完整准入**表的条目数 |
| $N_{entry,e}^{pre,P99}$ | 预先声明候选总体中，编译后、准入前条目的 P99，包含超过 $B_{GCL}$ 者 |
| $N_{entry,e}^{pass,P99}$ | 同一总体通过准入后的 P99，另报最大值 |
| $r_{entry,e}$ | 条目超限的已编译候选数 / 全部已编译候选数 |

编译失败但未生成可计数表的情况另计，不能混入分母使拒绝率变小。逐口拒绝率与整事务拒绝率分开。Oracle 内部搜索候选、统一离线压力候选、Actor 每周期单提案分别统计，不能混用尝试次数；只报通过者 P99 会掩盖真实条目瓶颈。若条目限制耗尽可行动作空间，E0 应据实停止学习控制，而不是训练后再发现。

#### 3.3 固定预约与旧表→新表拼接

C1 同时检查 AVB 固定源合同、CBS/信用规则与预约净服务证书（第二部分“系统模型”第 3 节）。2 ms 仅作软性能目标，不判安装失败。源突发和 ST 干扰界需覆盖上游聚集，不能用预测漏报概率代替硬边界。

过渡核验至少覆盖：正在发送的帧不被中断；旧表已发而新表才入下游的 TT；Q6 FIFO 及 Q7/Q4 积压；CBS 信用不清零；管理流与同步/版本偏差。冻结后的未知到达用合同边界覆盖，验证持续至旧状态安全吸收或进入已证明的不变集合。单轨迹离散事件验证是必要执行证据，但不能独自代替全部允许到达/状态的安全证明。

ST 的 $D_g$ 和 AVB 的 2 ms 都不是该验证器的性能安装门槛。任一硬验证失败、状态越出证书范围或来不及提交，整事务保持当前认证表并记录原因；若连当前表的合同条件也已被破坏，按系统故障报告，不能假设回退自动恢复保证。预约服务或全状态过渡证书未实现时明确标注原型边界，不要求第一阶段额外证明 AVB 2 ms E2E。

### 4. 统一时间的定时激活机制（Timed Activation）

本轮共同 baseTime 固定为 $t_{\mathrm{activate},k}=t_k+8$ ms，与第 4 ms 的冻结点分开。C1 通过后冻结事务版本和候选哈希；在不会提前生效的缓冲中预装，各口回报 PREPARED；C2 检查版本、参与者、哈希和共同 baseTime；C3 在 $t_c=t_{\mathrm{activate},k}-\Delta_{\mathrm{guard}}$ 前完成一致提交。只有具备完整提交依据的端口方可在共同边界激活；核验、预装或 COMMIT 提前完成均不得触发立即换表。

同一 baseTime 本身不保证跨设备原子性。可靠有界控制通信、可安全暂存/撤销和一致提交协议是部署条件；必须说明 COMMIT 丢失/设备故障时的处理。不能撤销或不能保证一致决定时，只能使用覆盖可能混合版本的证书，或将该能力限定为软件仿真，不写成已具备硬件原子提交。

### 6. 工程局限与训练前控制链基准

**局部信息与传播近似的边界。** 各口及前向消息均不独立证明全路径 ST 期限。组间联合假设、格内近似、未知冻结后到达、跨周期积压和最终安全修正仍限制收益。报告本地预测漂移、Mapper 校准/有效率、传播前后版本偏差、合同越界与安全干预；固定前向接口之外不增加反向性能通信、迭代重规划或预测网络。

**E0 前先测 4 ms，不等 MAPPO 训练后再测。** 在上述 Validator 与 Compiler 最小实现后，先使用相同规模的随机权重预测器/Actor、本地实测或压力事件规模及固定测试候选，基准测试。

整链预算沿用第二部分“本地观测与控制时序架构”第 1.3 节的 $T_{\mathrm{control}}\le4$ ms 及其统一分项定义，不另设预测器专属 4 ms 窗口。先导测量从 $f_k$ 的快照/特征构建起算，覆盖两层 Actor/Decoder/预检查、联合 Mapper、前向消息、汇集、投影、最终编译、完整核验、影子表预装与一致提交，并留足至 $t_k+8$ ms 激活的保护余量；不能只测模型 forward。

逐组件和完整链报告 P50/P95/P99/max、时限错过率、超时回退率及测试样本数。包括接近 256 条、需完整 FIFO/过渡检查且最终通过的慢例，不能只测快速拒绝或单口推理。共享 CPU/加速器争用、序列化通信、管理机会、非抢占阻塞和提交余量均计入；未测硬件通信/激活的部分明确为仿真假设，不冒充实测。

若整链 P99 已超过 4 ms，不能宣称已满足该部署目标；可在相同、如实计入的超时/回退模型下报告探索性性能，但正式“满足 4 ms”结论前须调整事件容量、批处理/模型实现、时间修正器或编译/验证实现，并用同一输入边界重新基准。主模型输入容量需处理峰值，任何事件截断规则都在训练前冻结、所有对照一致并报告丢弃率。P99 通过也不等于最坏时间保证，正式测试仍逐轮超时回退并报告 max/miss；本轮仅规定该先导准入，不填造耗时数字。

### 8. E0→E1→E1.5→E2 的证据链

实施顺序为唯一配置/全局流表→Compiler/真实 FIFO Validator→合法基线/包络→StrongStatic→E0 合法机会与完整 DAG 控制链基准→E1 本地预测→E1.5 服务映射/传播→E2 架构与训练闭环。参数、工作点、掩码、消息故障模型和统计口径在独立测试前冻结，不把本轮文档修订写成实验完成。

**E0：TT 整表重编排的物理与工程价值（H2）。** 主参数改为每流固定 500/1000 B、每源周期一帧；在每受控口约 15–30 条的初始探索量级内，由全局路由表派生成员和五周期配比。该量级仅指导先导探索，最终工作点由硬可行性、GB/Flex/GCL、AVB 预约和控制链预算共同选择，不预锁为 20 条，也不按最终测试增益挑选档位。

E0 不训练 PPO。先认证 TT/FIFO/期限、单事件六任务、AVB/CBS、条目与持续保持/过渡，再比较 StrongStatic 与 FixedOrderJointScheduleOracle。Oracle 仅有额外未来外生信息，按相同 fixed-order whole-table 时间权限逐候选回放真实网络，重算下游到达，不复用静态下游标签。至少确认两张不同整表可合法执行。固定候选分布、种子、预算，报告时间修正成功/超时、最终准入率、退化维、条目分位数/拒绝率及可获得的偏差界；不称精确可行体积。

H2 检验特权参考相对强静态是否有可重复的合法性能空间。差距不明确时先检查场景、权限、搜索预算/界，不把有限搜索失败称为物理无解。0.5 ms 分辨率诊断仍用第四部分固定其他口的单出口 Exact-Time/16-Bin 对照。ST 主截止期固定 1 ms，不能随差距改值。

同时用压力输入和随机权重 Predictor/Actor 先测完整两层 DAG 链，覆盖局部预检查、B/C 竞争、Mapper/通信、联合安全和提交；报告 P50/P95/P99/max、截止错过和连续保持。该基准无需训练好的策略，但不能省略主方法新增的阶段。未满足 4 ms 者公开原型边界，不用单口 forward 耗时替代。

**E1：每出口普通业务的本地预测价值（H1）。** 固定合法服务，只训练同一 Set Transformer+ModernTCN 预测器。六个 $(g,e)$ 逐一比较 Prior、BestSingleFlow、MultiFlow、SingleWindow/MultiWindow、均值池化、保边际跨流打乱；报告 AUPRC、Brier、NLL、校准、提前量与时间覆盖。使用本口全部可见 AVB/BE，不输入真实相关名单或路径。按自然发生率保留弱/无前兆，逐任务检查 $N=0,1,\ge2$；合同越界整次运行与全部帧单列，不按测试表现删样本。

H1 检验多流相对最佳单流与先验的增量；失败任务不能被宏平均掩盖。E1/独立合法改表校准后冻结 $\psi$，E2 各预测型方法共用；不新增 GNN、拓扑编码或预测网络。

**E1.5：传播是否提供动作条件到达信息（$D_{map}$）。** 在测试隔离的合法上游候选回放中，比较下游 $p^{loc}_{g,d}$、未经服务映射的上游预测平移对照（显式标为粗略基线）与 $p^{prop}_{g,d}$ 对真实 $t^Q_{g,J,d}$ 的 NLL、17 类 Brier、校准及正样本条件 bin error/$W_1$（记为 $D_{map}$，与第四部分 §6 衡量预候选到最终执行表漂移的 $D_{prop}=W_1(\mu^{prop,pre},\mu^{prop,exec})$ 区分）。PROB 模式三者的目标窗口、事件分母、冻结输入相同；INTERVAL 模式只报告覆盖与宽度，不对区间伪算点概率 NLL；上游真实未来日志只用于评测，不进入 Mapper。

按 $\|\delta_u\|$ 与实际解码时间移动量分层，分别覆盖 B/C 同现、先后颠倒、非抢占长残帧、已有积压、冻结→激活未知到达、窗口边界和消息失效。报告 Mapper 场景数/截尾、PROB/INTERVAL 各占比、消息有效率、区间覆盖/宽度、窗口外质量与全部样本覆盖；无效消息处主方法按固定本地回退，不能只展示易例。

“动作越大传播越有优势”是待检验假设。将 Mapper 误差与最终安全修正分开：在 $G^{pre}=G^{exec}$ 或受控合法候选固定的样本测服务映射本身；闭环全部样本再测 $D_{prop}$、$|q^{pre}-q^{exec}|$、$D_{sched}$ 和全表不变率，公开分层样本数。最终表不同引入的额外误差不能全部归责于 Predictor，也不能以离线重算的消息冒充在线输入。

**E2：闭环 E2E 收益与架构消融（H3）。** 运行第四部分九类比较，核心为 OwnerProp+MAPPO、LocalOnly+MAPPO、Local+Prop+MAPPO，另以 Local+Prop+IPPO 检验集中价值信息。Prior/Rule 对照保持同 DAG 和 Mapper，严格屏蔽实时包历史表示。共同使用相同合同、动作权限、安全链、五项回报和外生源种子；上游改表后各方法重算自己的真实下游到达/普通流观测。

重点检验 $\Delta_{prop}$、$\Delta_{local}$、$\Delta_{pred}$，同时报告真实计算/通信成本；主方法各端口按 DAG 分层，每轮只执行一次 Actor。MAPPO 相对 IPPO 的额外增益独立报告，不作为本地预测或传播贡献成立的必要条件。OwnerProp 对 LocalOnly 的直接差值不能单独隔离信息来源。

主结果并列报告 ST 全源帧 E2E miss/时延、逐任务本地预测与传播精度、消息有效率/故障回退、局部预检查和最终 Safety 干预、传播一致性、TT/FIFO/期限、AVB 预约与 2 ms 软目标、GB/GCL/TT 额外等待及完整控制耗时。成功激活与失败保持分开，不能只报成功表的性能。单出口/S0-only 是范围消融，不能代替四口主设。

所有实验按独立任务轨迹与多种子计算效应/置信区间，重复数由先导方差决定。源释放窗口的唯一帧构成评价分母；结束后按预定协议跟踪/排空，未完成/丢失保留并报告删失、合同越界与控制回退。只对已完成者计算的 P99 不冒充全量分位数；无法识别时给界或 N/A。

H1/H2/H3 与 E1.5 任一缺乏证据都据实收窄贡献；不通过安全层优化 ST、增加反向通信/重规划或新增预测网络补足。安全共同证据仍来自明确合同域下的认证与运行记录，有限轨迹零违约不能替代全域证明；AVB 2 ms 始终为软指标。

#### 外部对比（External Benchmark）与鲁棒性扫描（Robustness / Scaling）：与 Core 组主证据分步推进

在 Core 组（Topology-v1 九类主比较 + 4 核心方法在 $U^{TT}$/BE/ST jitter $\in\{\pm0.05,\pm0.10,\pm0.20\}$ ms 上的复核）完成后，依次推进外部对比与五个选定维度的鲁棒性扫描：

| 阶段 / 因素 | 预定范围与公平性 |
|---|---|
| **External Benchmark** | 在 **star（Topology-v1）** 与 **line（4 受控口串联拓扑 `Topology-Line-4`）** 上对比 **Ours / ARTSN (*ICDCS'23*) / E-TSN (*ICDCS'21*) / Period（标准周期静态表 $x^0$）**；共用相同物理速率、外生源轨迹、$B_{GCL}=256$ 与 Validator C1 硬合同底线，各运行原文调度/时隙释放机制 |
| **a. TT size / 负载** | 主设为每流固定 500/1000 B 及金字塔五周期配比（限制 $0.5/1$ ms 高频流条数防 GCL 分裂超限）；扫描档由全局流表派生，逐档重做实际条目计数、合法基线、包络及预约/过渡准入 |
| **b. Deadline** | ST 主截止期 $D_g=1$ ms 已冻结；其他期限只作预先声明的敏感性，重新推导 $d^Q$ 上下界与六任务传播界 |
| **c. GCL 内存预算** | $B_{GCL}\in\{128,256,512\}$（对标 Microchip LAN966x / Xilinx TSN IP 等硬件规格）；各方法同预算，重做实际条目计数、合法基线、包络及预约/过渡准入。未找到合法基线者记未准入 |
| **d. Path length / 拓扑规模** | 2/3/4-hop 路径长度变体（复用 `Topology-Line-4` 及子链，另可补充 8/12 受控出口固定路由 DAG branch 变体）；先验消息并图无环并逐拓扑重算合同、全局流表/负载和 E0，分别训练不称零样本泛化 |
| **e. Prediction noise / 相关性** | 在冻结 Predictor 输出 $(q^{loc},\boldsymbol\pi^{loc})$ 注入三档受控 Logit 高斯扰动与 Softmax 温度平滑 $\eta\in\{0.15,0.30,0.50\}$（同步流入本口 Actor 与上游 Service Mapper），重测 E1/E1.5/E2；亦可扫描生成器调制强度 weak/medium/strong |

这些是补充稳健性计划，不要求在 E0 可行性未确定前同时训练全部变体。主结论围绕“本地信息→合法时间自由度→动作条件前向传播→DAG 决策的 E2E 收益→合同/通信边界/一致性/控制审计”展开，不以模型名称数量或未验证的期望趋势代替证据。
